# FRIDAY — Voice Engine

The voice upgrade lives inside the existing voice stack. This is its single owning document: audit, module map, provider matrix, hardware profiles, and test evidence. Rules for the stack (Auto mode owns the microphone, both firewalls, hands-free off) stay in [AGENTS.md](../AGENTS.md) and [FRIDAY_STATE.md](../FRIDAY_STATE.md).

## Cloud realtime transport

`createRealtimeSessions().startCloud(id, provider, model, key, handlers)` opens one WebSocket to an address built from a fixed table (`CLOUD_REALTIME`, today `openai` → `wss://api.openai.com/v1/realtime?model=<model>`), with an `Authorization: Bearer` header. The renderer sends only a provider id, a model the owner named (none is defaulted, it costs money) and the consent flag. `main.cjs` re-checks consent, privacy mode and `paidUnlocked`, reads the key from the encrypted store, and the preload exposes no key. An error text is scrubbed of the key. Node's built-in WebSocket sends the header; this was verified on a local socket, which also reproduced the address and header the provider expects.

Unverified: a live session. The official OpenAI Realtime page could not be read from the build machine (the old guide URL redirects and the new one returned 404), so the `OpenAI-Beta: realtime=v1` header and the event names are taken from third-party examples and may differ from the current interface.

## Spoken text, playback and capture safety

- **SAPI text is data.** `electron/sapi-voice.cjs` `psLiteral` escapes the spoken text (curly quotes, `$()`, backticks, control and line-separator characters) and cuts it at 400 characters without splitting a surrogate pair. Test: `core/__tests__/sapi-voice-quoting.test.ts`. Curly quotes and Hindi through the real system voice are unverified on Windows.
- **One sentence splitter.** `splitSpokenSentences` (`voice-engine/language-segmenter.ts`) serves the spoken summary. `spokenSummary(text, { uncapped: true })` keeps every sentence for approvals, digests and reply pieces. Test: `core/__tests__/spoken-sentence-split.test.ts`.
- **Honest playback.** A clip that never sounded reports `none` (or `system` when the system voice spoke) instead of a neural result. One raw-sample failure turns PCM playback off for a cool-down that grows with failures in a row and is capped; `resetPcmPlayback` brings it back at once. Test: `core/__tests__/voice-playback-failure.test.ts`.
- **Capture.** The capture worklet is trusted only after its first frame, and its ring is emptied when the microphone closes (`core/__tests__/capture-worklet-liveness.test.ts`). The VAD noise floor stays frozen while speech is on and for a short tail after it (`core/__tests__/vad-floor-speech.test.ts`).
- **Wake word.** The wake name accepts Devanagari, nukta and two-token variants (`core/__tests__/wake-word-variants.test.ts`).
- UNVERIFIED: the cool-down values, the VAD floor and the worklet liveness on a real microphone, and the Hindi system voice list on the owner's PC (synthetic frames and fakes only).

## Echo cancellation: what is and is not known

FRIDAY's local neural voice (Supertonic) is played as an `Audio` element in the renderer (`voice-library.ts`), and the microphone is opened with the browser's echo, noise and gain flags (`voice-audio.ts`). Chromium's own canceller can use audio that the same renderer plays as its reference, so that path may already cancel most of FRIDAY's own voice; this was **not measured** here. System voices (`speechSynthesis`) and Windows SAPI play outside that path, so a reference signal for them is unknown. On top of the flags, the stack has a speaking guard, a louder-than-echo barge-in test and a self-echo transcript filter. For a realtime session's answer, which FRIDAY plays herself, a software canceller (`audio-aec.ts`) takes her voice out of the microphone before it is sent; that is tested on simulated rooms only. A measured test (play a known sentence, record, count leaked words) needs the owner's PC.

## FRIDAY Echo: a known-reference canceller for the kernel (2026-11-22)

`kernel/echo_canceller.py` is a canceller for barge-in whose reference is FRIDAY's own speech, so her voice can be taken out of the microphone while she talks. `EchoCanceller.process(mic, ref)` takes one 16 kHz mono int16 frame of each (bytes or a numpy array, same length as the microphone frame; `ref=None` means nothing plays). It keeps a ring buffer of the reference, finds the speaker-to-microphone delay by normalised cross-correlation on a 500 ms window (up to 400 ms, re-checked every 500 ms of audio while she speaks, no timer or thread of its own), lines the reference up and runs the SpeexDSP adaptive filter from `pyaec` (MIT, 83 KB Windows wheel, no torch). It is optional: a missing wheel or numpy, a silent or missing reference, an unsupported frame, or a filter that fails three times returns the microphone frame unchanged and never raises. The speech preprocessor of the filter is off, because it removed most of the owner's voice in the double-talk test.

- **Status.** Not wired into live capture. `voice_runtime.status()` reports `echo` and `echoCancellerReady`, and Doctor shows `echo-canceller` as OPTIONAL, never a failure.
- **Measured here (Linux, synthetic rooms only).** Echo reduction on the settled second half of 6 s, smoothed noise with a speech-like envelope through a delay, 0.4 to 0.5 gain and two reflections: 27.9 dB at 20 ms, 30.1 dB at 60 ms, 28.3 dB at 150 ms, 28.0 dB at 300 ms, delay found to the sample each time. With a 440 Hz owner tone under the echo (echo 1.5 dB louder than the owner) the tone stays at 80 % amplitude and ends 12 dB above the residual. About 0.13 ms per 10 ms frame.
- **Unverified.** A real speaker, room, microphone or Windows run; the Windows wheel loading; clock drift between the playback and capture devices; a reference pushed ahead of the sound that reaches the speaker (feed it on the microphone clock); non-linear speaker distortion, which a linear filter cannot remove. The renderer's own browser echo flags and the TypeScript canceller (`audio-aec.ts`) stay as they are.
- **Research record (2026-11-22).** ADOPT [pyaec 1.0.1](https://pypi.org/project/pyaec/) (bindings to [thewh1teagle/aec-rs](https://github.com/thewh1teagle/aec), repository MIT, SpeexDSP BSD; the wheel metadata carries no licence field; wheels for Windows x64 and arm64, Linux, macOS, no torch). The wheel metadata gap is why the licence is recorded here from the repository page.

## Task words and the voice state

`classifyVoiceControl` separates what a sentence controls. "Ruk jao", "stop", "chup" end speech only. A sentence that also names a task ("background task cancel karo", "task pause karo", "task resume karo") acts on the newest unfinished voice task and nothing else. The existing stop branch in `assistant-mode.ts` is unchanged and does not touch tasks.

## Hardware guide (for the owner's PC)

1. Open Settings → Voice. The card shows the profile chosen from the live reading of this PC (CPU threads, free RAM, video memory) and the models it would use. Nothing is applied or downloaded from there.
2. For a 4 GB NVIDIA GPU the rule is: speech recognition stays on the CPU (small, int8, beam 1, at most 4 threads); the GPU is kept for the language model; one background worker. If the card says Lite, free memory or CPU threads are low.
3. Larger models are never fetched without your yes. `checkModelFits` explains why a model is too big (RAM, disk, video memory).
4. To measure instead of trust: Settings → Voice → Speech model check (your own recordings), then watch "turn latency" in Voice diagnostics over a day.

## Running work in parallel

The Brain (`brain-engine.ts`) runs one turn at a time: one active run, one stream, one stuck-request watchdog. Two runs at once would need that engine rewritten around per-run state, and a real model stream cannot be driven here, so a second full lane was **not built** (a change that cannot be tested is a risk to everything that works). What already holds while a turn or a voice task runs, in Auto mode: a light remark ("how is it going") is answered at once and the turn continues; a short harmless question goes to the quick lane (`brain/quick-lane.ts`: under 160 characters, a question, no order word, nothing sensitive); any other request is acknowledged and queued, and runs right after (`whileBusy`, `queuedCommands` in `assistant-mode.ts`). So she keeps talking and nothing is lost, but action requests do not execute at the same time. These paths were not exercised by voice here.

## Round 2026-11-10: socket open, cancellation, codecs, transcript authority, wake, shadow evidence, validation harness

Linux build machine only (Node 22.23 and Node 26.13 LTS, Python 3.13). Nothing below was heard on a speaker, said into a microphone, run against a live Sarvam account or run on the installed Windows app.

### Streaming speech: the socket's own open

The IPC call that opens a stream used to answer as soon as the request was accepted, and the renderer marked the stream ready on that answer, so text could be sent to a socket that was still connecting and be lost. Now `electron/sarvam-stream.cjs` keeps a state per stream (`connecting`, `open`, `closed`), refuses a send until the socket's own `open` event (`that stream is still connecting`), answers the open request only after the real open (`whenOpen`), and abandons a socket that has not opened in 10 s (`OPEN_TIMEOUT_MS`). A close or an error before the open is an error, not a ready stream. The renderer (`sarvam-streaming-tts.ts`) is ready only on that open (an older main process that answers at once is waited for through the `opened` event, up to 12 s), releases a superseded or stopped start, and closes a socket that never opened so it cannot open late behind a REST fallback. The one-clause answer clock in `streaming-speak.ts` now starts when the text has been sent, so a slow first connection is no longer counted as a silent stream: the first sentence goes on the stream instead of falling back to the one-shot call.

### Audio cancellation

`stopSpeaking()` settles every pending playback and pause (`cancelHooks`), so a clip that was playing no longer leaves `speakText` waiting for an `ended` event that a pause never sends. A clip carries a `release` that gives back its media stream: `ProgressiveAudio.dispose()` (pauses the element, clears queued pieces, aborts an append in progress, ends the source, revokes the object URL, detaches the element; safe twice, before the source opens, and after an end). The speech pipeline releases clips made ahead of an interrupted clip, clips that arrive after it ended and clips of a failed pipeline; prefetched clips are released when they expire, are evicted or are reset. After an interruption the streaming voice drops its connection when the provider is still making the cancelled sentence (replies come back in order, so the next sentence would wait behind it) and opens a new one. `PcmPlayback` has a generation (moved on by `flush()`), refuses a late chunk of a cancelled answer, and `dispose()`.

### Codecs per transport

The WebSocket and the one-shot REST call have separate codec lists. WebSocket, from the provider's streaming page read 2026-11-10: mp3, wav, aac, opus, flac, linear16, mulaw and alaw are listed, default mp3. The app plays each clause through an audio element, so it requests mp3, wav, aac and flac on `bulbul:v4-flash`; opus is listed but the same provider reports it failing on its REST endpoint and nothing here has confirmed it on the socket; linear16, mulaw and alaw have no container to play. `bulbul:v2` and `v3` keep to mp3. REST (`bulbul:v3`, `v4-flash`): mp3, wav, aac, flac, linear16. `codecCapabilities(model)` exposes both.

### Sarvam final text as the input (an explicit option, off by default)

Settings > Voice > "Sarvam's final text starts the turn" (needs cloud voice and live captions on). In the default `captions` mode nothing changes: the stream draws words and the local recogniser makes the turn. In `sarvam` mode the Sarvam final is the input while cloud voice is on, Sarvam is allowed, privacy mode is off, a key is saved and quota is left, asked again for every final. The local final is held up to 1.5 s for the cloud one; if the cloud is first the local copy is dropped, if the cloud never answers the local text is used, and a closed gate or a lost stream releases a held utterance at once. A partial never starts a turn; a repeated final is dropped. Billing: the client counts the audio it sent, the provider reports the seconds it billed when the session ends, and the ledger gets the provider's figure once (the estimate only when the stream dropped first). The local recogniser keeps running (it is the fallback and the wake path), so this option adds cloud audio, not less local work.

### Wake word

`scripts/train-friday-wake.py` now trains on real recordings only (`validate`, `record`, `train`, `evaluate`). The model is a linear scorer over pooled log-mel features (`kernel/wake_features.py`, the code the app scores with), fitted with whole speakers and sources held apart in train, validation (threshold) and test (reported) groups. It is marked `production` only when the dataset is attested real speech (`PROVENANCE.json`) and not made of pure tones, has at least 60 takes from 3 speakers, 20 minutes of negatives including 10 near-miss clips, and the held-out test numbers are false rejection <= 5 % and false accepts <= 0.5 per hour over at least 0.1 h of unseen negatives. Otherwise it is written as a candidate the app ignores, and nothing can be written into `resources/wake` that does not meet the targets. The old tone-burst scorer is no longer shipped: it moved to `testing/wake-fixture/` labelled `synthetic-fixture`, `production: false`, and the kernel (`production_status`), the installer copy (`isProductionManifest`) and `verify-build.cjs` all refuse anything that is not a real-speech, evaluated model. FRIDAY therefore ships no wake model today and the transcript matcher answers; an existing install that copied the old scorer into `models/wake` is also refused. **No real recordings exist in this repository, so no production model was trained.** The trainer was run on stand-in band-limited noise only to test the code.

### Shadow interruption evidence

`BargeShadow` now reports each outcome once with the speaker and microphone levels; `ShadowLedger` keeps totals by outcome and speaker level, detector-minus-live lead times and the playback hours the detector listened for, across restarts. `shadowVerdict` applies fixed criteria (at least 50 live pauses, 2 hours of playback, 3 sessions, agreement >= 95 %, <= 2 detector-only interruptions per hour, 90th-percentile lateness <= 300 ms) and Voice diagnostics shows "not enough evidence yet" with the reasons; the copied diagnostics carry the full data. The detector still does not decide anything: the live path is the only one that interrupts.

### Hardware validation harness

`config/voice-hardware-validation.json` lists eight scenarios (Hindi/Hinglish/English recognition, Sarvam live captions, Sarvam streaming speech, real speaker playback, interrupting mid-sentence, no self-echo, a 30-minute session, microphone unplug/replug) with steps and numeric criteria; `testing/voice-hardware/phrases.json` has 24 phrases. `node scripts/voice-hardware-validate.cjs plan | init | score-stt | soak | check` scores word error rate, turns the app's soak record into the session numbers, and judges a report. `check` exits 0 only when the report's machine block says the installed, packaged app ran on Windows with named real devices and every metric meets its criterion with evidence noted; anything else prints `UNVERIFIED`.

### Fast first clause and raw-sample playback (2026-11-22)

Two settings, both on by default since the speed round (unverified on a real speaker), Auto mode and the local voice only; either can be switched off in Settings. Nothing leaves this PC; they move timing only.

- **`voice.fastFirstClause`** (`voice-engine/clause-chunker.ts`, used in `assistant-mode.ts` while no text has been spoken yet). The first clause is cut at a comma, semicolon, colon, dash or sentence end once it has at least 4 and at most 8 words and at least 18 characters; when no break comes within 8 words it is cut at the word limit. Every later clause is a sentence. A cut never lands inside a number (3.5, 1,000), an abbreviation (Dr., e.g.), a link, code, a quotation or a Devanagari word. Joined, the clauses read the same as the whole text.
- **`voice.pcmPlayback`** (`voice-library.ts`, `voice-engine/pcm-clip-player.ts`). Each local-voice clause is made by `speak-pcm` and played by `PcmClipPlayer` (the gapless WebAudio scheduler) instead of the audio element. Fallback: a clause that cannot be made as samples plays as a WAV clip; the first failure of any kind turns raw playback off for the rest of the session and `pcmPlaybackNote()` shows the reason in Voice diagnostics. Cloud voices never use it.
- **Measured** (Linux CPU, 7-word clause, about 3 s of audio): synthesis about 670 ms, real-time factor about 0.22. `speak-pcm` does not shorten synthesis (see Worker ops); the gain is the smaller first clause, and the player removes the file write, the read and the audio element start.
- **Unverified:** every number on the owner's PC; whether Chromium echo cancellation treats WebAudio output like an audio element; the sound of a clause boundary on a real speaker.

### Worker ops: `speak-pcm` and a provisional speech flush (2026-11-22)

Two additive ops for the voice mode blueprint. Neither is called by the live path yet; a later phase uses them behind settings, and the old ops, names and reply shapes are unchanged.

- **`speak-pcm`** (`kernel/voice_runtime.py --serve`, Electron `neuralVoice.speakPcm`, channel `voice:neural-speak-pcm`, preload `speakNeuralPcm`, ipc class `stream`). Request `{id, op:"speak-pcm", text, speed, lang, style, seq}`, reply `{id, ok, sampleRate, pcm16, ms, seq}` with `pcm16` base64 little-endian int16 mono. It runs the same `_speak_array` as `speak` (500-character cap, language spans, voice style), writes no file and has no sha1 cache. Samples equal the WAV path to within one sample (kernel test). Electron hands the renderer a `Buffer` (a `Uint8Array` after the structured clone, no base64 on the IPC hop). It is local only: no cloud voice and no SAPI fallback, so sensitive text never leaves this PC; on any failure the answer is `{ok:false, reason}` and the caller keeps the existing speak path. Empty or non-string text is `reason: "empty-text"`.
- **Provisional flush** (`kernel/stt.py` op `flush`, or `transcribe` with `provisional:true`; `voice:transcribe` payload gains `provisional` and `utteranceId`; no new channel, class stays `stream`). The worker streams the same partials, then answers the usual fields plus `final:false`, `audioMs`, `engine` and the echoed `utteranceId` (string, at most 64 characters). It is the same decode, so the no-speech policy, the noise-phrase and invented-text gates, the language lock and the script lock all apply; a provisional pass is never counted in the heard and dropped counters and never written to `voice-hearing.jsonl`.
- **Measured** (Linux CPU, scratch venv, real Supertonic 3, 7-word clause, 3.07 s of audio, warm, median of 8): `speak` to WAV bytes 670 ms, `speak-pcm` 684 ms, `speak-pcm` with base64 664 ms. The op saves the disk write, the file read and the WAV container, not synthesis time; the gain is for the first-chunk path, which needs a later phase to be measured. Supertonic draws random starting noise, so two calls differ unless the seed is the same.
- **Unverified:** the Electron IPC clone of the `Buffer` and the worker pipe on Windows, any speed on the owner's PC, and the live path (not wired).

## FRIDAY Tidy: cleaning the words shown for what the owner said (2026-11-22)

`src/lib/friday/voice-engine/transcript-tidy.ts` (`tidyTranscript`) is FRIDAY's own cleanup for Hindi, English and Hinglish: pure text, this PC only, no network, no storage, no model. It returns the cleaned text and a change list (`kind`, `from`, `to`) for a raw-versus-cleaned view, and returns the heard text byte for byte when nothing applies.

- **Spoken punctuation.** comma / koma / कॉमा, full stop / purn viram / पूर्ण विराम (a danda after Devanagari), question mark / prashn chinh, exclamation mark, new line / naya line / नई लाइन, new paragraph. The word is left alone after "the", "a", "word", "say" and similar, and at the start of a line.
- **Fillers.** Always whole words: um, uh, hmm, अम, हम्म. Words that are also real words (you know, like, matlab, woh, मतलब, वो) go only when the speaker set them off on both sides ("It was, like, big").
- **Backtrack.** "two, actually three", "John, I mean Jane", "nahi nahi teen", "scratch that", "no wait", "मेरा मतलब": the correction replaces the phrase it corrects, and corrections chain. Rule: a repeated phrase is replaced from its first word; otherwise the last word (or a run of number words or capitalised names) is replaced. "actually", "I mean" and "rather" need a pause (comma) before them or a number on both sides; "no no" needs no comma after it. Quoted or code text is never replaced.
- **Lists.** Only after the word list / suchi / सूची / लिस्ट: "one milk, two eggs" becomes numbered lines. At least two items, counted in order from one.
- **Dictionary and snippets** come in as data (whole word, case kept; a lower-case written form copies the heard case). `proposeDictionaryEntry(heard, corrected)` only proposes one entry from a single changed run; a swap of script is refused and nothing is saved.
- **Script policy.** Nothing is transliterated: Devanagari stays Devanagari, Latin stays Latin, digits stay as written (the number words are read only to find list markers and corrections). Quotes, `code`, links, e-mail addresses, paths and snake_case are never touched. The result carries `lang` and `romanHindi` from `scriptPolicy`; the number words come from `text-normalizer.ts`.
- **Wiring and setting.** `voice.tidyDictation` (default on, toggle in Settings, Voice) cleans only the words shown for a spoken line in Auto mode (`assistant-mode.ts` `tidyShown`); the caption carries `tidy: { raw, changes }`. The command sent to the Brain is never replaced. No separate Chat microphone path exists in the code.
- **Tests.** `core/__tests__/voice-transcript-tidy.test.ts` with `core/fixtures/voice-tidy-cases.json` (56 synthetic cases): output and change kinds, idempotence, no new script, switches, long and odd input, the learn helper, and the wiring.
- **Known limits.** Without a pause an "actually" is not read as a correction; a correction that replaces more than the last word and does not repeat the phrase replaces only the last word. Fixtures are synthetic; the spoken forms are not yet checked against the owner's real recordings (unverified).

## Speech Prep: Hindi and Hinglish read the way they are said (2026-11-22)

A pure text step on FRIDAY's reply right before the voice (`voice-engine/speech-prep.ts`, tables in `speech-prep-lexicon.ts`, numbers in `text-normalizer.ts`). It runs inside `prepareForSpeech`, before the text is cut into sentences and spans, so the echo filter compares against what is really spoken. Switch: Settings, Voice, "Speech Prep for Hindi and Hinglish" (`voice.speechPrep`, on by default, honoured on the speak path).

- **English inside Hindi.** In a sentence with Devanagari, a run of up to three English words is written in Devanagari from the lexicon (about 1,150 curated words: tech, apps, days, months, places, work, money, health, plain function words; a plural is derived). A longer run, a name the lexicon lacks and anything in quotes stay as written.
- **Roman Hindi (Hinglish).** Only when the speaking language is the Hindi voice and the Latin sentence holds two or more sure Roman Hindi words that are half or more of its words (about 380 words that are not English). Then the English words around them and the ambiguous ones ("do", "main", "to", "me") are written in Devanagari too. An English sentence is never changed, with or without the Hindi voice.
- **Never altered.** Quoted text, inline code (hidden before markdown is stripped), paths, addresses, words with digits or symbols, camelCase and snake_case.
- **Numbers (always on, not only for the Hindi voice).** Devanagari digits become digits first (Supertonic 3 rejects them); then words: Hindi 0 to 99, hundreds, hazaar, lakh, crore; negatives; decimals; ordinals (पहला ... पाँचवाँ, 21वीं, 3rd); dates day first and year first; time the Hindi way (सवा तीन, साढ़े तीन, पौने चार, a "बजे" that follows is not said twice); rupee, paise, "₹5 lakh"; percent; a phone number digit by digit.
- **Cost.** One pass; the tables are parsed once. Measured on this Linux machine: about 1,700 characters per millisecond (116,000 characters in 69 ms), a 200-character reply well under a millisecond, and text built to hurt regular expressions under 800 ms. The 800 ms voice budget is untouched.
- **Research (2026-11-22).** The English to Devanagari lexicon of `sulabhkatiyar/indic-tiny-tts-hindi` (code MIT, weights CC-BY-4.0): its licence file does not cover the lexicon data or its cmudict and IndicXlit sources, so **REJECT** as a data source; FRIDAY's own table is written instead.
- **Unverified.** Every Devanagari form and Hindi number word was written from knowledge and checked by test only: **not heard** through the voice. Correct a word through the pronunciation dictionary (it wins). A real reply read by the Hindi voice on the owner's PC is the check.

## Voice mode round 2026-11-22 (2): draft mode, prewarm, echo reference, language, task rules

Built and tested on Linux with fake devices only. Nothing ran on the owner's Windows PC, a microphone or a speaker.

- **Early (speculative) start.** One gate, `eagerAllowed`, decides whether a stable partial may start a guess: Auto only, no Stop everything, not paused or muted, not booting, not in a call hold, FRIDAY not speaking, no pending read-back or approval, not sensitive, no approval or authority words; with "only my voice" on there is no early start because the speaker is unknown before the final transcript. One function, `discardEager`, ends every guess (pause, mute, Stop everything, barge-in, new speech, leaving Auto, a changed partial, a different final). The guess is the Brain's draft: `startDraft` (or `send(.., {draft:true})`) is a text-only run with no tools, no approval, no memory write, no history row and no run row, at most one live and one per turn, 10 s lifetime, only to a local or proven-free model, never in privacy mode or for a sensitive line, an order or a live-data question. `adoptDraft(id, finalText)` promotes it to a real run only when the tidied final words equal the words it started from and privacy, paid access and approval level are unchanged; otherwise a normal turn runs. The renderer sends `draft: true`, Electron forwards a strict boolean `ephemeral`, and the kernel `chat.stream` then stores no chat row, keeps the active session, does not mirror to the phone, writes no memory, offers the model no tool and refuses a tool call it makes anyway (`NO_TOOLS`, a context variable in `kernel/router.py`; model choice and both firewalls are unchanged). Pinned by `voice-eager-guards`, `brain-draft-mode`, `chat-ephemeral-forward` and `test_chat_ephemeral.py`.
- **Run ownership.** `send(prompt, {owner:{kind:"task", taskId}})` tags a run; `stop()` (default `"all"`) is Stop, Clear chat, the tray pause and the kill switch; `stop("foreground")` (barge-in, the stop word, a change of mind) leaves task-owned runs running; `stop({taskId})` ends one task. Stop everything and the tray pause cancel every desk task (CANCELLED, no "Done: X. Stopped."). `askBrain` finds its run by id. A quick-lane answer is captioned and spoken at once (`brain.onQuickAnswer`). Pinned by `brain-run-owner` and `voice-tasks-flow`.
- **Prewarm** (`voice.prewarm`, default on): one pass after the microphone opens in Auto (`voice-engine/prewarm.ts`, engines in `voice-prewarm.ts`): speech engine (a silent provisional decode), kernel connection (no model call), local voice (three words, discarded), Smart Turn on silence, acknowledgement lines in memory. Never in Chat or Manual, before the mic opens, while muted, paused or stopped. A failed step is a Voice Doctor warning, never a toast.
- **Played text** (`voice.trimHistoryToPlayed`, default on): `voice-engine/played-text.ts` records each clause; at a judged real interruption the next turn is shown only the heard part plus a marker (`Message.playedText`, `truncateAssistantReply`); the stored reply stays whole.
- **Echo reference.** `voice-engine/echo-reference.ts` taps what the PCM scheduler plays (windowed-sinc resample to 16 kHz, one 8 s ring on the audio clock plus output latency) and gives one aligned reference frame per microphone frame; `audio-aec.ts` takes it through `processWithReference`; the kernel op `echo-shadow` and the channel `voice:echo-shadow` (class stream, one call per 160 ms, base64 cap 8192, local only, no disk or log) report levels only and never gate. The canceller in `audio-aec.ts` is a PHAT-weighted delay search, a proportionate NLMS filter, a 2.5 s warm-up that passes audible reference through until the filter is trusted, a double-talk freeze (the filter stops adapting while the owner speaks), drift tracking of the clock offset, an optional residual suppressor (`suppressor`, off by default) and passthrough after 5 failures in a row. Simulated-room echo reduction (ERLE), before then after the upgrade: 40 ms delay 20.5 to about 41 dB, 90 ms 18.4 to 38-51 dB, 250 ms 21.4 to 32.5 dB, noisy microphone 18.3 to 34.4 dB (synthetic rooms and a simulated clock only). In live capture it is wired behind `voice.echoReference` (default off); see the per-utterance cancel section. Unverified: real speakers, Chromium's own cancellation, the Windows `pyaec` library, device clock drift.
- **Language.** The English Speech Prep table has 1,628 words. Sentence cuts are shared by TypeScript and Python (`splitSentences` / `split_sentences`) through one fixture; an abbreviation, initial, decimal or URL never ends a sentence, and the TypeScript splitter is linear. Speech numbers cover ranges, 12 am/pm, 24x7, years by language, Hindi day ordinals, +91 numbers, paise, fractions (आधा, तीन चौथाई, डेढ़, ढाई, साढ़े, सवा, पौने) and Indian grouping up to 99 crore. Known gaps: English dates still say "two thousand twenty six"; numbers from 1e9 stay digits.
- **Rules for talking while tasks run (built, not wired).** `voice-engine/utterance-router.ts` (one rule order for every heard line), `speech-arbiter.ts` (priorities approval > direct > progress > chatter, FIFO when equal, never cut a clause, quiet grace 600 ms) and `narration-policy.ts` (never says links, paths, code, secrets or invented percents; meetings, quiet hours, mute and sensitive content respected) are pure and pinned (214 tests). The conductor does not call them yet: a short question 5 s after a long task is still queued, a background task's streamed answer is still voiced as foreground then repeated by "Done: X", the "Started: X" line is still held until the next LISTENING entry, a background approval is still silent, and a call or quiet hours do not gate task lines (nine skipped target tests in `voice-tasks-flow.test.ts` and `voice-eager-guards.test.ts` pin them).

## Voice mode round 2026-11-22 (4): instant acknowledgement, task desk, echo in capture, Hindi extras, security fixes

Linux unit tests with fake devices only. Nothing was heard or spoken on the owner's Windows PC, and no weights were run on Windows.

- **Instant acknowledgement** (`voice.instantAck`, default off). After the endpoint is confirmed `shouldAck` decides; one timer fires at the endpoint plus 600 ms and the pre-rendered local clip (rendered at prewarm only when the setting is on, `voice-engine/ack-player.ts`) plays through the speech queue as a direct line. ## Voice mode round 2026-11-23: confirm questions, language packs, closing pause, auto language

- **Yes/no questions are rare.** `voiceNeedsConfirmation` in `voice-session.ts` asks only for irreversible actions (always), cautious ones (Balanced) and broad ones (Ask every time). `voice.confirmLevel` (rare, normal, always; default rare) tunes it. A read-back of what she heard needs a doubtful transcript (mean token log-probability at or below -1.0, or language confidence under 0.5), one question per turn, and a 60 s cooldown. Thresholds are untuned on the owner's PC.
- **Language packs.** `voicePacks` in `model-catalog.ts` group the existing pinned members for English, Hindi and Hinglish; the Models page card installs one pack with progress and cancel. No new weights; the pins stay in `electron/voice-pins.cjs`.
- **Closing pause.** The smart-turn model runs inside the speech worker (`score-turn` op, cached ONNX session, about 50 ms instead of 480 ms or more for a fresh process; the one-shot spawn is the fallback and a busy worker answers "busy"). It is asked after 240 ms of quiet; a confirmed end (0.6 or more) closes at 280 ms; a low score waits to the cap; a score that has not come back is never waited for past the plain pause. The decode no longer scores the turn unless `turn_score` is requested.
- **Recognition language defaults to auto** on a fresh install (stored values are kept). Hindi chosen or auto is heard by the Hindi ear first; faster-whisper takes over when the ear's mean token log-probability is below -0.40 (hi) or -0.33 (auto). The Hinglish ear still listens only in hi-Latn. The `load` op warms the model; the prewarm names the listening language.
- **Auto model size.** Under 4 GB RAM tiny, under 8 GB base, en-US base, otherwise small; larger sizes only by owner lock.
- **Measured (Linux 4-core, synthetic speech, noisy):** smart-turn spawn 472-518 ms before, 47-60 ms warm in the worker; Hindi under auto 3.0-4.0 s at WER 0.33-1.0 before, 0.23-0.44 s at WER 0.0-0.08 after. Not measured: Windows timing, real microphones, natural pauses at the 0.6 confirmation.
- **Not built:** Hinglish ear for mixed speech, persistent score op in the TTS worker. (The provisional adopt-on-equal decode was built later: see "Early read of the closing pause".)

## Idle unload and memory pressure (speech worker)

- The speech worker keeps its models only while they are used. After 10 idle minutes (a request can set `idleUnloadSec`; 0 turns it off) the faster-whisper model and the Hindi ear are unloaded and the next turn reloads them. The `status` op reports `loadedModels`, `loadMs` per model, `idleSec`, `lastUsed`, `unloadCount` and a `fallbacks` counter (`cuda-to-cpu`, `ear-to-generic`, `model-to-windows-speech`, `hindi-ear-to-whisper`, `low-memory-resident`, `low-memory-refused`).
- Memory pressure (ok, high, critical) is read with GlobalMemoryStatusEx on Windows and /proc/meminfo on Linux, with no extra package. High is under 15% free, critical under 7%. Under high pressure the worker never opens a model larger than the resident one: the resident one answers, or a smaller one replaces it after eviction. An unreadable machine reads as ok.
- On a PC with 16 GB or less, an automatic pick of medium, large or turbo under pressure is refused with the `low-memory` fault; an owner-locked size is not refused (the resident model answers under pressure and it is counted).
- Unverified: the live GlobalMemoryStatusEx call, real RAM return after unload, and the idle thread against the Electron worker on Windows. Not wired yet: `electron/stt.cjs` and the diagnostics do not read the new status fields; `hindi_ear.unload()` does not exist (stt.py resets its fields).

## Voice privacy (no raw audio by default)

No raw audio is saved by default. Three things can hold voice data on this PC, and `electron/voice-privacy.cjs` knows all three:

- the enrolment samples and encrypted voiceprint (`electron/voice-enroll.cjs`);
- the utterance WAVs the speech worker keeps only when the owner turns on "Keep my spoken clips for diagnostics" (`voice.keepUtteranceWavs`, off by default; `voice.utteranceWavDays`, 1 to 90, default 7; folder `debug/reports/utterances`);
- the consent record (`preferences/voice-privacy/consent.json`: the time the owner agreed and a notice number, nothing else).

Settings > Voice > My voice > Privacy has the agreement button, the retention toggle with days, and "Delete my voice data" (click twice), which removes the enrolment files and voiceprint, the kept clips and the consent record, then says what went and what is left. ## One final, one turn; one TTS interface; FRIDAY voice profile

- **Duplicate finals.** `voice-engine/final-dedupe.ts` holds back the same words (case, punctuation, danda, digit script folded) from the same utterance id, or inside 4 s with no reply between. A deliberate repeat after a reply began, or after the window, passes. A short answer (5 words or fewer) while an approval is open always passes once, a stop word always passes, and a provisional line never reaches it. Folding does not transliterate: "haan" and "हाँ" are different keys; the arbiter's pairing covers that case.
- **One TTS interface.** `voice-engine/tts-provider.ts` (`TtsProvider`, `TtsFallbackManager`) ranks cloud (router-allowed), online, light Hindi, local Supertonic, system voice, formant, under the existing privacy, sensitive-line and billing rules. At most 2 voices per clause; the engine changes only at a clause boundary; a voice that fails before sound is replaced, one that fails after sound began is kept; chunks of another generation are dropped; the actual engine and fallback reason are reported. `tts-ladder.ts` and `speech-tts.ts` delegate to it and `voice-library.ts` clip makers run through it.
- **FRIDAY voice profile.** `voice-engine/friday-voice-profile.ts`: one model-independent identity (female, Hindi and English, rate 0.6 to 1.6, pitch -4 to +4 semitones, pronunciations, model references with licence lines from `model-catalog.ts`), read from and written to the existing voice preferences (no new store). `profileFits` and `rebindModel` let a new model take the same profile. No imitation of a real person; cloning from recordings is out of scope.

## Security fixes after review (2026-11-23)

- The smart-turn score goes to the speech worker only when it is loaded and has nothing queued; behind a load or reload it answers "busy" and the turn closes on the plain pause, so the 20 s score deadline can never kill a half-loaded worker.
- A kill during a revision swap leaves the verified copy as `<id>.swap`; the next swap or audit renames it back, `.swap` is never deleted while it is the only copy, and a failed rollback is reported with its reason and the `.prev` folder name.
- The idle watch in `kernel/stt.py` survives a bad value (huge numbers clamp or are ignored) and an exception in one tick.
- Unverified: Windows rename and locking behaviour of the swap recovery.

## Confirmation classifier hardening (2026-11-23)

- A line that starts with a question word is exempt only when it truly asks about the risky word ("how do I delete a file", "is it safe to uninstall"). "What time is it, delete my files" is judged per clause (comma, question mark and exclamation mark are clause breaks) and asks. A safe-looking shell guess ("go ahead and delete the folder") no longer hides an irreversible order.
- `remove <thing>` (except bookmarks, tabs, filters, reminders and list items), `format D:`, `email/message <person>`, switch off or hibernate, write over, drop database, execute the payload and "download and run" ask at Balanced; disabling the network adapter or running a downloaded binary is a caution. The spoken question is trimmed from the filler, never from the object or destination.
- Heuristic lists: "remove X" and a leading "message <word>" may ask a little more than needed. Not checked against "go ahead and ..." phrasings: `extractSandboxRun` and `isRoutineSandboxCommand` keep their own short-circuits.

## Per-utterance TTS cancel (2026-11-23)

Research (2026-11-23): Deepgram Flux TTS interrupt handling (send Interrupt, drop frames in transit), KugelAudio barge-in (cancel one TTS context, keep the socket, drop the tail), LiveKit's playout pipeline (clear audio that arrived but has not played when the speech handle is cancelled). ADAPT: cancel scoped to an utterance id with the worker kept alive and the result dropped by id; FRIDAY has no stream to flush, so the cancel is a reader-thread line plus a stop check between language spans. REJECT: killing and respawning the worker (loses the loaded model, costs seconds). Unverified: no worked example of a between-chunks cancel flag was found, so the check mechanics are FRIDAY's own design.

## Early read of the closing pause: cancel op and adopt-on-equal (2026-11-23)

The smart-turn score arrives about 290 ms into a pause, and the pause may run on to 650 ms or more. In that gap the speech worker was idle. Now the audio so far is read at once (a provisional decode); if speech resumes the read is cancelled, and if the pause closes on the same audio that read is the final answer and no second decode runs.

- **Research record (2026-11-23).** ADAPT Deepgram Flux eager end of turn ([docs](https://developers.deepgram.com/docs/flux/voice-agent-eager-eot)): start work at a medium-confidence end, treat resumed speech as the cancel signal, reuse the draft only when the end-of-turn transcript matches; their warning that eager work costs 50-70% more calls is why the read here is gated. ADAPT LiveKit preemptive generation ([turn tuning](https://docs.livekit.io/agents/logic/turns/tuning/)): reuse when the context is unchanged, redo when it changed, skip long turns; a reported bug there (cancel arriving after the work finished) is why a late answer is dropped by a flag and a generation counter. ADOPT cooperative cancel: the faster-whisper README says `segments` is a generator and the work runs as it is iterated ([README](https://github.com/SYSTRAN/faster-whisper)), so a flag read between segments and passes is the only stop it offers. REJECT killing the worker to cancel (a reload costs seconds and drops the warm model), REJECT a second worker for early reads (doubles RAM on a 16 GB PC), REJECT decode-and-discard without a cancel op (the final would wait behind it for nothing).
- **Kernel** (`kernel/stt.py`). Op `cancel` `{utteranceId}` (empty id: whichever provisional read runs). The worker now reads its input on its own thread, so a cancel is answered while a decode holds the main one; every other request still runs in order and only the cancel jumps the line. `check_cancel()` is read before and after each segment, before the ear, before a model opens, before the language re-check and before each hearing pass. A cancelled read raises `DecodeCancelled` (a `BaseException`, so no `except Exception` in the ladder can turn it into a Windows-speech fallback), answers `{ok:false, reason:"cancelled", cancelled:true, final:false}`, and is never counted as heard or dropped and never recorded. Only a provisional read can be cancelled: a cancel for a final decode does nothing. A cancel that arrives before its read begins is remembered (32 keys at most) and spent when it begins. The worker leaves with `os._exit` after a flush so the reader thread cannot block interpreter shutdown.
- **Electron** (`electron/stt.cjs`, channel `voice:cancel-transcribe`, class quick). A provisional read takes the turn gate only if it is free (`tryEnter`): it never queues behind or ahead of a final decode, and answers `busy` at once otherwise. It runs only on the local speech worker that is already loaded (`not-ready` otherwise, also for any cloud or one-shot engine: a guess is never sent off the PC or billed). The cancel does not enter the gate: it marks the read and writes one `cancel` line to the worker, which is not killed and has no pending entry. The answer of a cancelled read is always `cancelled`, even if the text had just finished.
- **Renderer** (`voice-stt.ts`, `voice-engine/provisional-decode.ts`). After the score answers 0.5 or more, in quiet, with the worker free, from the PCM ring, and not while spoken clips are kept for diagnostics, one read of the audio so far starts (one per pause). Speech resuming (or a new utterance, or stop) cancels it and bumps the generation. At the close the window is sealed: it is the same audio only if the first samples match a fingerprint, the tail is no longer than the time that passed (and at most 1.5 s), the gate's quiet clock never restarted, and the decode options are equal; otherwise the read is cancelled. The sealed read travels with its utterance through the queue; `send` takes its answer instead of decoding again, and falls back to the normal decode for a busy, failed, empty or cancelled read. The score of 0.6 or more closes at 280 ms, before a read could start, so that path is unchanged; the gain is for the 0.5 to 0.6 band and for turns the text rule holds open longer.
- **Gates.** No early read when recent final decodes averaged over 1.2 s (a cancelled read holds the worker for the rest of its first window), and none while more than a third of the last 8 reads were wasted (retried after 6 utterances).
- **Measured** (Linux 4-core CPU, synthetic clips of 2 to 7 s, warm worker over the real `--serve` line protocol, median of 2, closing pause 650 ms, score at 290 ms; first final = time after the end of speech until the text exists). base: en_short 1918 to 1523 ms, en_long 1830 to 1494, hing_short 1627 to 1294 (saves 0.33 to 0.40 s). small: 3312 to 3184, 3780 to 3469, 3880 to 3367, 3593 to 3065 (saves 0.13 to 0.53 s; small is gated off here since it decodes in about 3 s). The gain cannot exceed the gap between the score and the close (about 0.36 s). Cost when speech resumes 0.3 s after the read began and the final leaves 0.2 s later: the final waits for the rest of the read, base +0.5 to +0.85 s, small +1.3 to +2.6 s over a plain decode. The gates above exist because of that number. A hi_short run on base took 21 s with or without the change (base model on Hindi, not this work).
- **Known limits.** The first window of a read cannot be interrupted (CTranslate2), so the cancel saves the later passes, not the model call it is inside. The worker counts an adopted read neither as heard nor as dropped (the page counts it). Unverified: everything on Windows, a real microphone, how often real owners resume after a 0.5 to 0.6 pause (the gates assume under a third), and the owner's decode time (the 1.2 s gate and the 0.34 share are Linux-derived).

## Voice round 2026-11-24: stable partials, backchannel gate, played-ms cut, push-to-talk tail, wake guard, engine registry

- **Stable partials** (`voice.liveWords`, off by default). `transcript-stabilizer.ts` `LocalAgreementStabilizer` over timed words: each pass is shifted to one clock, words starting at or before the last committed time minus 0.1 s are dropped, a repeat of the committed tail (up to 5 words) within 1 s is stripped, the longest common prefix of two passes is committed (the first pass commits nothing), the rest is shown dim, a committed word never changes. `live-words.ts` timed mode waits about 0.5 s of new audio, never runs two passes, waits 1.5 times the last pass, trims the buffer at a committed segment end after 15 s and at the last committed word after 24 s (never over 30 s), cancels a pass in flight with the existing cancel op, reuses the last confident language and re-detects every 4th pass. After a reading, up to 4 segments (15 s of audio at most) whose script disagrees with the decode language are decoded once more with their own language and kept only when the script and length fit.
- **Engine chooser.** `choose_tier` picks an engine only when `voice.streamEngine` asks for one and every pinned file is present at its exact size, numpy and onnxruntime import, and the locale is one the model lists; otherwise the reason is returned and the ordinary path runs. Under `auto` it also gates on speed: `RtfLedger` keeps the real-time factor each engine measured on this PC per hardware tier (`small-cpu`, `mid`, `gpu`) in `<models>/stream-ear-rtf.json`, and an engine measured slower than 0.6 is skipped next time. An engine not measured yet is tried; an engine named in the setting is not gated.
- **Fallback.** Any refusal, throw, stall or empty final ends the stream and the same audio is transcribed the ordinary way (`stream-session.ts`). The ear's partials are display data and never reach the Brain; the final goes through the same gates as a transcribed one (wake, voice match, tidy, ITN).
- **Trelis Hinglish candidate (ADAPT, opt-in on a GPU; see "The Trelis Hinglish ear").** Whisper large-v3 fine-tune by Trelis Research (Apache-2.0), int8 CTranslate2 conversion by a community account, pinned as `hinglish-ear-trelis` (`nikh360pro/capsbro-hinglish-ct2`, 1,556,723,863-byte weights; the licence file travels with them). It writes Hindi in Devanagari and English in Latin letters in one line, through a mixed-code marker (token 51866) that the decoder prompt writes by id. It is on demand only and GPU-class (4 GB video memory, `cpuOk` false). Linux-sandbox numbers, not the owner's PC: 3,042 MB peak memory after load, a 15 s clip decodes in about 5 to 10 s on 4 CPU threads (slower than speech); the publisher's WER table (CoSHE-500 13.7%, cs-fleurs 10.2%, FLEURS Hindi 12.6%) is a lead, not a FRIDAY measurement.

### Speech gate, text gates and one-word clips

- **Silero ONNX gate** (`kernel/vad_onnx.py`; the pinned 2,327,524-byte file, no silero-vad pip package): speech opens at probability 0.5 after 3 frames in a row (96 ms), is kept until the probability falls under 0.35 (a value between the two flips nothing), a burst shorter than the minimum is cancelled, and the 500 ms before the start (the withheld onset frames included) is returned with the start. The scorer is injectable, so every rule is tested with made-up probabilities and no model. A failure mid-stream drops to the energy gate.
- **Transcript gate** (`kernel/transcript_gate.py`; the gates that lived in `stt.py` moved here and are re-exported): a compression ratio above 2.4 marks a repetition loop; a speech fraction under 0.3, or under 120 ms voiced, is not speech (600 ms voiced always is); a per-language table of stock sign-offs (English, Hindi, Roman Hindi) is dropped when short and weakly supported, so a real sentence that contains one is untouched; CTC and transducer readings need a mean token confidence of 0.35, since they give no no-speech probability.
- **Short-clip rule.** A reading under 600 ms is accepted only when it snaps to the command lexicon (`haan`, `nahi`, `ruko`, `stop`, `ok`, `theek hai`, and more) or has confidence 0.6. The batch path's VAD parameters keep a 120 ms word reaching the decode.
- **Long form.** A clip over 30 s is cut at its silences into pieces of at most 25 s with 1 s overlap and a seam dedupe (`kernel/stt.py`); the renderer keeps a segment open for up to 5 minutes and spills audio at quiet places instead of cutting at 20 s (`voice-stt.ts`). The worker's transcribe deadline is the model's load budget or three times the clip length, whichever is longer, for a 16 kHz mono WAV (`electron/stt.cjs`).

### Turn protocol and eagerness

The stream-feed reply carries `turn` (the last note) and `turns` (all): `start`, `partial` (the full text so far, one `turnId`), `eager`, `resumed`, `end`, `revised`, each with text, speech probability and speech milliseconds, plus `env`, `speaker` and `needsWake` when those scores are on.

- Silence rules are today's: 420 ms in an open conversation, 700 ms waiting for the wake word, +780 ms when the text trails off, never above the preset's longest wait. The word list adds Roman Hindi and Devanagari fillers and conjunctions (matlab, woh, umm, haan toh, aur, ki and their Devanagari forms); digits and spelled letters hold the turn longer.
- About 200 ms after the gate stops, the pinned Smart Turn v3.2 model (`voice_runtime.score_turn`, last 8 s) scores the turn once on a background worker (the verdict applies on the next feed call), and again after speech resumes: 0.6 or more closes the turn at 280 ms; under 0.5 waits long; no file or a failure leaves the silence rules alone.
- Presets map `eagerness` to base and longest wait: eager 300 and 1,600 ms, normal 500 and 3,000 ms, patient 800 and 6,000 ms. **Normal keeps today's 420 and 700 ms**, so the default changes nothing the owner hears; only a turn the model calls unfinished may wait up to the longest.
- `eager` is sent only with `eagerTurn` on, a 200 ms gate stop and a Smart Turn score of 0.5 or more, and is always followed by `resumed` or `end`. The renderer starts a draft on it (`startDraft` with `onlyLocal: true`: a cloud model is never called for a guess), cancels it on `resumed` and adopts it when the final text is equal.

### Room and speaker score; barge-in ladder; Brain hints

- **Score only.** `kernel/ear_scene.py` reads each 1.5 s window by DSP (spectral flatness, tonality, the 4 Hz syllable wobble, run length without a 300 ms pause) into speech, music, tv or noise; speech with no pause for about 12 s reads as TV or radio. At a music or TV score of 0.6 (two windows in a row, leaves under 0.4) the gate start is raised to 0.6 and a final of fewer than 2 words is dropped; `wake-guard.ts` raises the wake threshold by up to 0.15 for 4 s after the last tag. The speaker score is a WeSpeaker int8 cosine against the owner's voiceprint: owner at 0.5 or more, other under 0.25, unknown between or whenever a part is missing. **A speaker match never approves anything, never lowers a threshold, and is never read by approval code** (tests pin it); with `hold` the note carries `needsWake`, which the renderer does not read yet.
- **Barge-in ladder** (`BargeLadder`, opt-in): echo-cleaned speech for 150 ms ducks her by 12 dB, 500 ms or one real word stops her (resumable), no real word by 2 s lets her carry on; "haan", "hmm", "ok", "acha" never stop her, and duration alone does not inside the 1 s windows around her turn start and end. It acts only on echo-cleaned speech, so her own voice in the microphone cannot stop her. The played milliseconds go on the turn record. The default gate (duck 0.3, minimum 400 ms, 2 words) is unchanged. The ladder is effective only when an echo-clean source exists (the streaming ear is on, or the echo reference is live); otherwise the default gate decides. Settings shows a helper line, and the Doctor row `ears-bargein` reads "on, but not active" with the reason.
- **Brain hints** (`brain/turn-hints.ts`): five fields are read (language, mix, confidence, eager, clipped), nothing else. The reply mirrors how the owner spoke (Hindi in Devanagari, English in Latin, a real mix answered in a mix, over 15% of the minority script). Under 0.45 ear confidence (0.55 for a clipped line) the Brain asks one short question instead of acting, never twice in a row (30 s window), and **never echoes a heard secret, a digit run or other sensitive text back**. Hints carry no authority: they can only make FRIDAY say less or ask once. A confirmed read-back, an approved command (a spoken yes or the on-screen button; the hints are stored with the pending command) and a queued request replay with the hints they were heard with (confidence dropped and the clipped flag set on confirm), never the hints of the spoken "yes" turn. The Doctor rows `ears-turn` and `ears-scene` fill from the stream turn path (`noteEarsTurn`); `TurnTracker` keeps `lastEndMs` and `lastEnv`.

### Setup, Doctor and IPC

- **Setup** fetches the streaming ear only when the voice plan says this PC can carry it (`streamEarDecision` in `electron/voice-weights.cjs`): not the lite profile, not a low-end processor, its 1.8 GB recommended RAM inside the speech budget, the disk with headroom, and never on a metered line, on battery or under heavy load; a verified copy is reused. It is one more row of the plan (`plan.streamEar`), kept out of the planned download total. **It is optional: a failed fetch is a NOTE that names the fallback (the turn-by-turn ears), never a FAIL**, and the Doctor shows it missing but not required. The Models page and the Install Manager fetch it on any PC. Setup and Doctor on Windows are unverified.
- **Doctor** rows: `ears-vad`, `ears-turn`, `ears-clip`, `ears-agc`, `ears-denoise`, `ears-scene`, `ears-bargein`, each a real value or an honest "absent", plus the pin row `stream-ear-nemotron-pin`.
- **IPC**: `voice:stt-stream-open` (payload: locale, hotwords up to 64 of 40 characters, `ears`, owner embedding read in the main process), `voice:stt-stream-feed` (up to 1 MiB per call) and `voice:stt-stream-close`, all budget class `quick`; worker deadlines 25 s, 8 s and 20 s, a stream idle for 15 s is dropped.

### Evaluation

- `npm run voice:bench -- stt-stream` feeds each recording to the streaming ear in 160 ms chunks and scores it with the one scorer the tests pin (`voice-engine/transcript-scorer.ts`, twin `kernel/stt_bench.py`): a folded word error rate (script folded so a Roman and a Devanagari spelling of one word match), T-WER (transliteration-mapped, over the Hinglish lexicon), the switch-point error rate (errors at the places the language changes), first-word and final latency, partial flicker, and a regression gate against an earlier baseline. It writes `<root>/reports/stt-baseline-<engine>.json` on the owner's PC only (a root inside the repository is refused); exit 2 with no number when weights, a hash or the scorer refuse.
- `kernel/stt_bench.py` counts only an EndOfTurn event as the endpoint and reads an optional manifest key `speechEndMs`; the denoise A/B skips a denoiser that failed mid-run. The Hindi stream with hotwords keeps the same noise and unsure gate as the plain reader (CTC confidence is the mean greedy-path log-probability; its -0.40 floor is looser than the plain reader's; **unverified on real speech**), and the live Whisper stream refuses the Trelis folder. Nemotron chat model ids stay chat in `electron/model-capabilities.cjs`; only the ASR ids are audio. All of this is unverified on a real microphone, room or Windows.
- `kernel/ears_eval.py` scores the ears in seven numbers: gate frame F1, onset delay, clip-start loss, end-of-turn delay, premature-cut rate, non-speech text rate (with 95% ranges) and false turns per hour. `--synthetic` renders the scenes in `core/fixtures/ears/manifest.json` with numpy (no audio in the repository) and measures the harness and the energy gate, **not** the speech model or the owner's microphone; `--owner` reads his labelled recordings and skips visibly without them.

### Denoisers, the Trelis Hinglish ear, the owner centroid and the review

- **Denoisers (optional, on demand, never bundled).** `dpdfnet2` ([Ceva-IP/DPDFNet](https://huggingface.co/Ceva-IP/DPDFNet) at revision `dd6818d0`, `onnx/dpdfnet2.onnx`, 10,178,747 bytes, Apache-2.0): 16 kHz, 10 ms hop, model delay 640 samples, real-time factor 0.16 on Linux. `gtcrn` ([TigreGotico/audiosronnx-gtcrn](https://huggingface.co/TigreGotico/audiosronnx-gtcrn) at revision `eeba5e96`, `gtcrn_simple.onnx`, 535,638 bytes, MIT): streaming export with 3 cache tensors, real-time factor 0.06 on Linux. Both are pinned by size and SHA-256 in `electron/voice-pins.cjs`; the real-time factors are Linux numbers, not the owner's PC. `kernel/denoise_onnx.py` runs them with numpy and onnxruntime only and returns the input unchanged on any error (missing file, wrong size, load or run failure). **Wired, default off:** `AsrLane` in `kernel/stream_ear.py` gives a denoised copy to the speech engine only (the transducer and the LA-2 engine); the speech gate, Smart Turn, scene, speaker and every gate read the raw audio. The model delay (640 samples for `dpdfnet2`) is aligned out. A missing or failing model falls back to raw audio with a reason, and the `rnnoise` value has no streaming wrapper, so it runs raw with a reason. `denoise {engine, active, rtf, latencyMs, reason}` is in the stream-open reply and the final reading. Verified only with injected graphs on Linux; a real `dpdfnet2` or `gtcrn` run and the real word-error effect are UNVERIFIED.
- **The A/B rule.** `kernel/ears_eval.py --denoise-ab` scores the same labelled clips raw and through each denoiser. A denoiser is kept only if the word error rate does not worsen by more than 0.5 point and the share of no-speech clips that still produce words does not rise. Every verdict stays UNDECIDED until the owner's labelled clips with a `text` field exist under `<FRIDAY_ROOT>/voice-eval/ears`; the synthetic scenes cannot decide it.
- **The Trelis Hinglish ear.** Pinned `hinglish-ear-trelis`: a GPU-class optional candidate, downloaded on demand from the official pin, never bundled. It is opt-in only: a request must name it (`hinglish_ear: "trelis"` or `"hinglish-ear-trelis"`); no language, mode or default selects it, and Settings has no control for it yet. The hardware gate (`trelis_verdict` in `kernel/whisper_ears.py`) needs every pinned file at its exact size, a CUDA GPU and at least 4 GB of video memory read from `nvidia-smi` (or `FRIDAY_GPU_VRAM_GB`); an unknown value refuses, and only `FRIDAY_HINGLISH_EAR_FORCE` or the request's `hinglish_ear_force` bypasses the hardware check, never the file check. The marker contract: the decoder prompt is `<|startoftranscript|>`, `<|hi|>`, the mixed-code marker, `<|transcribe|>`, `<|notimestamps|>`; the marker is written as literal id 51866 because `tokenizer.json` stops at 51865, and the ear refuses to open unless `vocabulary.json` holds `<|mixedcode|>` at that index. A live pass never decodes with this folder (it has no marker prompt). Any refusal (`not-installed`, `no-gpu`, `vram-unknown`, `vram-too-small`, `failed-before`) or a failed decode returns to the engine of today, and the reason is reported. Accuracy on his real voice and other people: unverified.

### Review fixes, speed and int8 measurements (Linux only)

- **One voice per utterance.** A clause that fails fails with reason `engine-failed`; it never switches to the package voice mid-utterance. A request without an utterance id falls back whole. The package fallback never speaks delivery tags.
- **Reply identity.** Every `speak-pcm` reply carries `engine`, `own`, `voiceId` and `recipeVersion`, plus a `fallback` kebab token only on fallback paths. `op:'status'` of the running worker returns the live view (`live:true`, failures, `engineState`); otherwise Doctor says "cold view".
- **Cache and warm-up.** The WAV cache key includes the recipe version and the answering engine; fallback replies are never cached. Warm-up retries up to 3 times. `sampleRate` is clamped to 8000..192000.
- **Taint.** A spoken run that read tool, web or file output never applies delivery tags; tags are also stripped from untrusted screen text. `kernel/router.py` tool payloads still carry tags to the model; the run is tainted so they never reach the voice.
- **Picker.** The voice picker is accessible: icon-only row previews are labelled, and previews are disabled outside Auto with a hint.
- **Time to first sound** (Linux 4-core, box load 1.5 to 4, n=200 per setting, 40 clauses in Hindi, English, Roman Hinglish and Devanagari Hinglish; median ms for 1, 2, 3 threads): steps 3 524 / 350 / 353; steps 4 661 / 403 / 434; steps 5 766 / 470 / 517. Two threads is as fast as or faster than three on a 4-core box; the default (cores divided by 2, capped at 3) gives 2. By clause length at 4 steps and 2 threads: 3 words 289 ms, 6 words 403 ms, 12 words 1017 ms, so a short first clause is the lever.
- **int8 dynamic quantisation** (measured, not shipped). All-ops QUInt8 loads on this onnxruntime: estimator 256 to 65 MB, step 12 to 15% faster, clause RTF 5% better, round-trip CER 0.069 fp32 against 0.074 int8. MatMul-only gives no speed-up. Verdict: not shipped, below the 25% bar; it would need an owner-hosted converted file.

## Voice phase 1 and follow-ups: what is wired now

Evidence is Linux unit tests only. Windows, a real microphone and a real speaker are unverified for every row; the owner-PC list is at the end of this section.

### Resources and the speech worker

- **Thread budget.** Every voice model session takes its thread count from `kernel/voice_budget.py` `steady(role)`, never from its own constant. The steady cap is 6 threads.
- **One worker module.** `electron/voice-worker.cjs` owns the long-lived Python child for both the speech-to-text worker and the speech worker (one JSON line per request, replies matched by `id`): single-flight start (the first start gets 90 s), light cached `status()`, soft timeout means slow and a hard deadline kills the tree, a crash-loop breaker (3 crashes in 60 s opens it for 5 minutes, then one probe), idle unload from the stored profile. While the speech worker is in a crash loop on Windows a final goes to the offline Windows recogniser (one rung) instead of only pausing; unverified on Windows.
- **Stream warm.** The `stream-warm` op (`voice:stt-stream-warm`) loads the streaming ear before the first turn on its own thread. Every model load asks `kernel/stt.py` `admit` first: a load that would leave too little free memory drops resident models in a fixed order (stream, fast, whisper, Hindi ear) and is refused when it still cannot fit; a decode that is running is never evicted, the warm takes the admit lock without blocking and answers low-memory instead of waiting.
- **Smart Turn** scores on a background worker; the verdict applies on the next feed call. End-of-turn scoring sends audio bytes to the warm worker and a cold worker is skipped without a spawn.
- **Error text.** Every speech error text is path-scrubbed (`scrubPaths`) before it leaves the main process.

### Shared tables, language and the reading check

- `config/hinglish-lexicon.json` (version `hinglish-lex-3`) is one word table read by the renderer, the kernel and the word-error scorer; `config/sensitive-markers.json` is the one sensitive-marker table read by the renderer, the Electron privacy firewall and the kernel (recalled memory counts as owner text). Doctor shows a repair row when either file is missing.
- The reading check (`kernel/tts_eval.py`, 50 lines) reads the voice back through the local ears. Roman Hinglish is scored on a folded form, and temperatures are read with their degree words. The committed baseline for `hinglish-roman` is CER 0.174 (WER 0.442, 6 lines) with a margin of 0.06; recent loaded-box runs read 0.154 to 0.194. This is a recogniser read-back, not listening; Windows and a speaker are unverified.
- `scripts/build-hinglish-lexicon.cjs` is an offline, one-time proposal builder: it reads datasets the owner fetched outside the repository, never edits the lexicon, never uses the network and refuses an output folder inside the repository. Its WER fixture holds hashes only.

### Speaking

- One ladder, `src/lib/friday/tts-ladder.ts`, ranks every speaking path. FRIDAY Voice is the default online, offline and in privacy mode; a cloud voice is used only after an explicit pick, and a sensitive line or privacy mode never reaches one.
- The echo window follows the clip length and its playback backlog. An acknowledgement clip plays only when the expected wait is over 1500 ms (`ACK_THRESHOLD_MS`) and the first clause is six words. The speaker restarts itself after two failures.
- Voice data delete counts what it removed, never follows a link out of its root, and also removes the local reply clips in the reply cache (a 40-hex name with a `.wav` or `.mp3` extension) and the 16-hex temp clips. It does not remove a whole folder.

### Wake, hands-free and turn control

- The live wake scorer uses `max(manifest threshold, 0.5)`. A second-chance window, scene-bound transcript wakes and a speaker block exist and are off by default; a follow-up chain closes after three turns, 60 seconds or a TV scene.
- Hands-free starts off, and only a stored boolean `true` restores it.
- Wake guard second pass (`src/lib/friday/wake-guard.ts`, off by default): `secondPassMargin` (0 to 0.2, default 0) answers a frame score just under the bar with `verify: true` and still refuses; the caller may pass back one short transcript check as an utterance within `VERIFY_WINDOW_MS` 1500 ms, and it goes through every gate. At most one ask per `VERIFY_SPACING_MS` 5000 ms (and `VERIFY_PER_MINUTE` 12), and none while a scene, noise or ultrasonic raise is in force. Counters: `verifyAsked`, `verifyAccepted`, `ultrasonic`. Built and unit-tested on synthetic frames, but **no live caller sends the check yet**. `ultrasonicShare` (0 to 1, default 0) raises the bar like a music scene when frames carry energy above 17 kHz; **unverified**: the renderer captures at 16 kHz, which cannot see above 8 kHz, so it has no real input.
- The pure turn engine and the interruption classifier run in **shadow** beside the live controller. The shadow keeps agree and disagree counts; the classifier never acts, the live controller decides. Moving a decision to the engine needs the counts on the owner's PC first.
- Wired in Auto mode: the codemix transcript, a closed-vocabulary command lane, addressedness, spoken self-repair with a read-back, and the turn hints passed to dictation. The approval window follows its preference (`voice.approvalTtlSec`, 10 to 60 s).
  - **Command lane** (`commandLaneTakes`, `voice.understanding.commandLane`): stop, mute and open only, and open only for names in the owner's `voice.vocabulary`. It never bypasses the wake gate (an unaddressed line may only quieten her while she speaks). A snap to a consequential name is read back and waits for a fresh yes; an open still goes through the normal risk and approval path.
  - **Addressedness** (`addressednessAddsWake`): a TV or music scene, another voice, a doubtful decode or a stale conversation may only add a wake requirement; it never lowers one and never accepts or approves a line.
  - **Self-repair** (`selfRepairOf`, `voice.understanding.selfRepair`): the repaired line runs; a consequential repair is read back and waits for a fresh yes, which then passes every check. The raw words go to the audit.
  - **Spoken confirmation** (`askToConfirm`): the full digest is read only when it names an amount or a person or place; any other hard order keeps the short question. One spoken correction is applied and read back; a second correction cancels. A yes that began before the corrected digest never approves. A doubtful yes gets one re-ask, then is ignored until the window ends or the owner confirms on screen. Her own playback coming back (`ownPlaybackHeard`) is dropped. A cloud voice call passes the billing state and fails closed (`billingAllowsPaidNow`). A yes counts only if it began after the full read-back (or the task prompt) finished sounding; a yes of unknown start is treated as early and asked again. Self-repair never runs on an answer, and every yes is judged on the raw words as heard, so "no, I mean yes" cancels. A TV, music or other voice can only refuse, never approve. Stop everything, the tray pause and mute drop every waiting approval, so a later yes binds to nothing. Stop and later words ("stop", "not now", "later", "ruko", "baad mein", in Latin and Devanagari script), "why not" and "not a problem, go ahead" count as no; laughter is unclear and never a yes. For a hard order the short question must finish before a yes can bind, and a read-back cut before its end (a barge-in, a cough) is asked again in full. Every case fails safe. Linux unit tests only (`core/__tests__/voice-approval-safety.test.ts`, `voice-turn-sim.test.ts`); no real speech or microphone.
  - **Barge-in classifier** logs in shadow only and never acts. The shadow turn engine sees only scrubbed text (at most 80 characters of a partial, nothing of a private line), is dropped on Auto exit, Stop everything and mute, runs after the live action, and is rebuilt when `voice.turn` changes. The speech breaker and install state feed the voice ladder, and the barge-in detector reads the echo-cleaned level when the echo reference runs. `TaskSpeechRouter` drops a cancelled task's late result; `narrateTask` voices the rest.
  - **`voiceTurnContext`** builds the turn-context block as pure data; nothing sends it yet (it waits for the Brain dispatch wiring, AM6c).
  - Evidence: `core/__tests__/voice-understanding-wiring.test.ts` and `voice-confirm-digest-wiring.test.ts`, Linux unit tests on synthetic turns. Approval timing is pinned in `voice-approval-safety.test.ts` and shadow hygiene in `voice-shadow-hygiene.test.ts` (synthetic timings; the Brain approval path is covered by source pins only). Real Hindi and Hinglish digest read-back, the real microphone and the speaker are unverified. Real player end times and microphone speaker tags are unverified.
- Spoken voice preferences (`brain/voice-preferences.ts`, capped at 300 tokens) are staged with a read-back and stored only after a short spoken yes within 30 s; forget, clear and list exist.

### Echo canceller

The own canceller (`voice.echoReference`, default false) counts a frame as cancelled only after its attenuation has held for `SETTLE_MS` 250 and the measured echo return loss enhancement is at least `TRUST_ERLE_DB` 3 dB (`echo-live.ts`), so her own echo no longer reads as the owner. `voice-aec-room.test.ts` simulates one room (150 ms path): her echo drops by at least 15 dB, the owner's level stays within 1.5 dB, barge-in fires within 400 ms of his onset. A simulated room is not a real room: the setting stays off until the A/B on the owner's PC (speakers, then a Bluetooth headset in the hands-free profile) shows the same.

### Auto bar, diagnostics and evaluation

- The Auto bar shows one phase chip (spoken only for confirm and stopped), hands-free and dictating chips, a level meter painted without a timer (`VoiceLevelMeter.tsx`, `voice-live-status-model.ts`), and the last turn's first-sound time. Its real look is unverified.
- Voice diagnostics lists the live microphone's asked and reported echo, noise and gain settings.
- `scripts/wake-soak-eval.py` is scorer-only (the transcript matcher and wake guard are not in its numbers). `meetsTargets` is true only for a bed of at least 6 hours, at least 60 positives, at most 0.5 false accepts per hour (95 % upper) and a miss upper limit of at most 5 %. No bed has been run.
- `kernel/uia_overlay.py` is a pure builder that numbers the targets of an accessibility tree and speaks their labels; it has no click path and nothing calls a click from it.
- `core/__tests__/voice-offline-turn.test.ts` runs a whole Auto turn on the turn simulator with every network and cloud channel replaced by a tripwire: no call is made, cloud lanes default off, and sensitive lines and privacy mode never reach a cloud voice.

### Hinglish frontend, delivery tags, timing

- **Frontend** (`kernel/tts_frontend.py`, standard library only). It guards what the renderer's Speech Prep left and cuts the reply into clauses the engine reads one at a time (`prepare`, and `clauses` for streamed fragments; any fragmentation gives the clauses of the joined text). Mixed Hindi and English clauses are read as Hindi. Roman Hindi is written in Devanagari before reading: on the fixed Hinglish set the round-trip CER is 1.4% with that step against 22% to 31% when the same words are read as written in Roman letters (Linux proxy, recogniser read-back). A character the engine cannot read is removed, never spoken as a name. Each clause carries `lang`, `pause_ms` and `first`.
- **Delivery tags** (`kernel/tts_delivery.py`, renderer side `src/lib/friday/voice-engine/delivery-tags.ts`). Vocabulary and allow-list: `warm`, `soft`, `excited`, `calm`, `slow`, `fast`, `pause` (also `pause:ms`), `breath`, `sigh`, `laugh-soft`, each with an optional strength (`[warm:0.5]`); any other bracket word is dropped, never spoken. Tags are trusted only for FRIDAY's own text in voice mode; text from a tool, a page, a file or a person is read untrusted, so its tags are removed and none is applied. A tag in code, a link or touching a digit is plain text. At most two mood tags per sentence act; every number is clamped. The renderer removes the tags from everything shown on screen, so they are invisible to the owner. The engine's own angle tags (`<laugh>` and the like) are disabled for now: measured, the engine reads them aloud as words in some languages, so `ENGINE_TAG_STATUS` keeps every one off and a clause never carries an angle bracket.
- **Joins, word timing, backlog.** `playback-scheduler.ts` overlaps the edges of consecutive clips of one utterance with an 8 ms equal-power seam and fades the start and every stop (4 ms), so joins and cut-offs do not click. `played-text.ts` and `kernel/tts_timing.py` give each clause weighted word times (syllable-like units plus the pause punctuation asks for) so a cut-off remembers the words really heard. The scheduler reads its queued-audio backlog; below 120 ms the next clause is kept short, so the speaker does not run dry.
- **First clause.** The opening clause of a reply runs 4 steps (the other clauses 5) and a long first sentence is cut short at a comma. Measured read-back: 4, 5 and 8 steps are equally intelligible, 3 steps are intelligible to the recogniser but were never listened to (hissier by proxy), 2 is not intelligible.

### Speak contract and status

- **Request** (`speak-pcm`, `kernel/voice_runtime.py`, forwarded by `electron/neural-voice.cjs`): `trusted` (true only for FRIDAY's own words, lets tags act), `first` (opening clause), `pauseMs` (silence after this request, 0 to 1200), plus the voice id. A request with none of them behaves as before.
- **Reply**: the audio plus `pausedMs` (the pause really added) and `wordTimes` (`word`, `startMs`, `endMs` per word on the clause's own clock; estimated, not aligned). The Electron side passes both back after checking their shape.
- **Warm-up**: the `warm-up` op opens the engine, runs one tiny synthesis and one short clause through the whole path (persona, trim, chain); the renderer sends it once, so the first reply does not pay for the graphs and the blend.
- **Status** fields: `ready`, `engine` (`friday-voice`, `supertonic-3` as the fallback, or `none`), `own`, `voice` and `voiceId`, `sampleRate`, `recipeVersion`, `reason`, `offlineFallback`, `cloud`.
- **Picker and Doctor**: Settings, Voice lists FRIDAY (default), FRIDAY Bright, FRIDAY Calm, then F1 to F5, M1, M2; a stored value outside the list reads as FRIDAY, an explicit F1 to F5 stays as chosen. Doctor shows a "FRIDAY Voice engine" row and an active-voice row (Warning, with install steps, when the worker sent no status) and a voice-diagnostics row set (`src/lib/friday/voice-doctor.ts`, `voice-diagnostics-rows.ts`).

## FRIDAY Runtime: one door for every own model session

`kernel/friday_runtime.py` (config `config/friday-runtime.json`; Linux unit tests in `kernel/tests/test_friday_runtime.py` and `test_runtime_single_door.py`; nothing run on Windows, a GPU, a microphone or a speaker).

- **One door.** Every own voice model session (ears, speaker, light roles, wake word, self-test) opens through `open_session`, with the thread budget of its role from `voice_budget`, so roles that run together never ask for more threads than the PC has. A test pins that no other kernel module opens its own session.
- **Hash once per file stamp.** The pinned SHA-256 of a model file is checked once per file stamp (size and modified time), not on every open.
- **CPU fallback.** When a session cannot open on the chosen provider it falls back to the CPU provider.
- **Outside the door.** The `supertonic` and `onnx_asr` packages open their own sessions. `onnx_asr` now receives the budgeted options (`session_options`); `supertonic` is unchanged.
- **Graph cache.** `optimized_cache` in `config/kernel.yaml` is off by default (`FRIDAY_RUNTIME_OPTIMIZED_CACHE` overrides it).
- **Doctor row.** Voice diagnostics shows a FRIDAY Runtime row with the engine version and providers, and a plain not-ready reason when the kernel cannot answer (`electron/voice-verify.cjs`, `voice_pin_selftest.py --runtime-info`).
- **Own build of the engine (optional).** `node scripts/build-friday-runtime.cjs` builds the engine from the official source pinned to `v1.32.0`; it is recorded only after its smoke test passes, is never part of the Windows build chain, and the runtime reports it only when the installed wheel matches the pinned hash (the official engine otherwise). Status: not built yet. The official source could not be fetched in the cloud session; the owner can run `node scripts/build-friday-runtime.cjs` on his PC (unverified).
