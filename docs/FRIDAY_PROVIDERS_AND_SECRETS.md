## 3. Keys

`electron/credentials.cjs` stores secrets under `<FRIDAY_ROOT>/security/credentials` via Electron `safeStorage`. The renderer never holds a decrypted key. A “connected” badge is written only after a live list/probe succeeds (`electron/models.cjs`). Connected means AUTHENTICATED + MODEL_CATALOGUE_AVAILABLE. It does not mean a free model is LIVE_CHAT_VERIFIED.

**Secret storage uses only the asynchronous `safeStorage` API** (`isAsyncEncryptionAvailable`, `encryptStringAsync`, `decryptStringAsync`; the synchronous methods are removed in Electron 46). One module, `electron/secret-box.cjs`, talks to it for provider keys (`config/provider-keys.json`, `electron/models.cjs`), every other token (`security/credentials/secrets.json`, `electron/credentials.cjs`), the voice profile (`electron/voice-enroll.cjs`) and the voiceprint (`electron/voiceprint.cjs`). Researched 2026-11-17 from the [Electron safeStorage page](https://www.electronjs.org/docs/latest/api/safe-storage) and the installed `electron.d.ts` (45.2.3): ADOPT, because 46 removes the synchronous methods and the async ones decrypt what the old ones wrote.

- **Format and location are unchanged.** `{ "<id>": { "enc": "<base64>" } }` in the same files; a plain string written before encryption existed is still read. Nothing stored is re-saved just to read it. Electron documents that `decryptStringAsync` opens `encryptString` data and does not say the reverse works, so going back to a build before this change after new secrets were saved is not supported.
- **Reads stay synchronous, writes are asynchronous.** After Electron is ready, `main.cjs` opens every stored secret once (`primeSecretStores`, bounded to 5 seconds so a slow keystore cannot hold startup) into an in-memory map of ciphertext to clear text. Callers such as `getSecret` and `readKeys` read from that map; nothing in it is written anywhere or sent to the renderer. A secret not opened yet reads as "not set" until it is. `setSecret`, `writeKey`, `voiceprint.save` and the profile save are `async`.
- **Writes are queued per file and atomic.** Each write re-reads the file inside a queue, changes one entry, writes a temporary file and renames it, so concurrent writes cannot overwrite each other and a failed write (disk full, antivirus lock) leaves the old file whole and reports an error. A credential file that exists but is not valid JSON is never overwritten.
- **Unavailable encryption never becomes silent plain text.** A packaged app, or a workspace with Settings → Security "refuse unencrypted" on, refuses the save with the same message as before. Only an unpackaged developer build or the test suite may store a plain string, and the result then carries `encrypted: false`. Before the app is ready `available()` is false, so nothing is encrypted or stored early.
- **Rotation (`shouldReEncrypt`).** `decryptStringAsync` resolves `{ result, shouldReEncrypt }`. When it is true FRIDAY calls `decryptStringAsync` again once, as the API says, uses that answer (or keeps the first if the second fails), then re-encrypts the entry in place under the write queue. The entry is rewritten only if it is still the same ciphertext, and if encrypting or writing fails the old ciphertext stays and still opens.
- **A keystore call that never answers.** Every OS call (availability, encrypt, decrypt) is limited to 10 seconds (`secret-box.cjs` `withLimit`). A hung encryption fails that one save with an error and the write queue moves on; a hung availability check reads as unavailable (a packaged app then refuses the save); a hung decryption is retried later and is not remembered as unreadable.
- **A ciphertext this account cannot open** (another PC or Windows account) stays in the file untouched, reads as empty, is not retried in a loop, and survives later saves of other ids.
- **A historical `github.json` token** is erased from that file only after the encrypted store accepted it.
- Tests: `core/__tests__/secret-box-async.test.ts` (41 tests, a mocked `safeStorage` and synthetic secrets only). The mock proves FRIDAY's side of the contract; that real Windows DPAPI opens ciphertext written by an older build with `encryptString` is Electron's documented behaviour and stays unverified on a Windows PC until the owner checks.

## 4. Firewalls

- Billing: `electron/billing-firewall.cjs` is the desktop authority and `kernel/billing.py` applies the same class before a kernel request leaves the machine. A paid or unknown-cost model is never a silent default. Cost policy: `src/lib/friday/brain/cost-policy.ts`. Every local engine id (`ollama`, `llamacpp`, `lmstudio`, `vllm`, `localai`, `jan`, `mlx`) is billingClass `free`. A cloud model is free to dispatch when `electron/model-access.cjs` has official free evidence (`ZERO_COST`, `FREE_QUOTA`, or `FREE_CREDIT`, eligible or rate-limited, from `provider_pricing`, `provider_free_plan`, `provider_model_catalog`, `provider_trial`, `provider_router`, `owner_declared`, `live_probe`, or `local_runtime`) or a verified free probe. Verification may still be `UNVERIFIED`. A stale price (`pricing_stale` or `evidence.stale`) stays unknown. Listing a model is not that evidence. An API key alone is not paid authorisation. The shared cases are `core/fixtures/billing-access-records.json`.
- Privacy: `electron/privacy-firewall.cjs` plus `kernel/privacy.py` — SENSITIVE payloads hard-stop. A financial block is a real card (Luhn), an Aadhaar-shaped group, a PAN, or a passport, SSN, Aadhaar, or PAN word followed by an identifier. The blocked line names that signal and says to remove it or run a local model. Local engine ids are never treated as leaving the machine.
- Owner text and recalled memory: `ownerText` (an attachment, extra text, every recalled line and the prompt) is screened whole and per part in the renderer (`src/lib/friday/brain-engine.ts`, cap `OWNER_TEXT_CAP` of 400k characters), in main (`electron/privacy-firewall.cjs`) and in the kernel (`kernel/privacy.py`). A cut or over-cap text counts as private and stays off the cloud. Spoken digit runs, number words, Devanagari OTP, CVV and passcode, and "verification code" with up to 10 tokens before a 4 to 8 digit value are SENSITIVE rows in `config/sensitive-markers.json`; the code-phrase rows allow grouped digits and a longer gap; contact regexes are bounded. Recalled memory reaches the model as one user-role block of untrusted data (`kernel/router.py`). An allowlist of owner sources (`user`, `owner`, `chat`, `voice`, `teach`, `friday`, `conversation-state`, `cognitive-baseline`; `src/lib/friday/brain/quoted-data.ts`) decides what is the owner's own text; every other source is quoted as outside data. Tests: `core/__tests__/egress-full-prompt-screen.test.ts`, `core/__tests__/privacy-spoken-otp.test.ts`, `core/__tests__/memory-quoted-data.test.ts`, `kernel/tests/test_privacy_markers.py`, `kernel/tests/test_privacy_redos.py`. UNVERIFIED: the false-positive rate of the new spoken-code rows on real speech.

Network: `electron/net-fetch.cjs` (Windows proxy / TLS).

## 5. Free vs paid cloud models

Classification lives in `electron/model-access.cjs` (used by `electron/models.cjs`, `electron/model-router.cjs`, and the billing firewall). There is one catalogue and one router. A name containing “free”, a `:free` suffix, a provider free tier, a free signup, Studio/web/chat access, or a successful `/models` listing is a **signal**, not proof. The canonical access object retains provider/model/endpoint/wire, normalized pricing, entitlement/quota/rate-limit evidence, capability metadata, live chat/stream proof, TTL timestamps, health and failure reason.

Billing modes: `ZERO_COST` (official API price is $0), `FREE_QUOTA` (eligible free-plan/rate-limit quota), `FREE_CREDIT` (trial / promotional / grant credits covering this call), `PAID`, `UNKNOWN`. `creditSource` is `TRIAL` | `PROMOTIONAL` | `GRANT` | `USER_FUNDED` | `UNKNOWN`. Only TRIAL / PROMOTIONAL / GRANT may produce `FREE_CREDIT`. A user-funded or unknown balance is `PAID` or `UNKNOWN`, never free. Eligibility: `ELIGIBLE`, `RATE_LIMITED`, `EXHAUSTED`, `NOT_ELIGIBLE`, `UNKNOWN`. Verification: `VERIFIED` only after the existing chat probe succeeds. Official free evidence is coarse `free` while verification stays `UNVERIFIED` until that probe. `UNKNOWN` is never converted to free by a name or a successful call alone.

Free-only routing is fail-closed: `filterByTier(..., "free")` and `selectEligible` with `free-only` never fall back to paid or unknown models (`NO_FREE_MODEL_AVAILABLE`). HTTP 429 is `RATE_LIMITED` / `FREE_RATE_LIMITED`, never paid. HTTP 402 blocks the call but does not overwrite the model's underlying pricing evidence. Exhausted free credits stay `EXHAUSTED`; they are not silently billed. Live verification is **lazy**: classify from official evidence, filter capability + route mode + owner pool + cost policy, rank candidates, probe only a candidate the request can actually use, cache proof per key/model/tier (~30 minutes), then try the next eligible candidate only when required. A successful call on an unknown-cost model proves chat access, not a free entitlement. Stream and non-stream verification are retained separately. Renderer selection IPC, one-shot kernel writing, desktop chat, and phone fallback consume that routed pool; unpublished live routing, invalid explicit ids, and cooling-down ids fail closed instead of widening to the kernel's independent catalogue. Only `multi` fans out concurrently.

Where a vendor has no machine-readable free/pricing API, FRIDAY keeps isolated official knowledge with `checkedAt`. A source is re-read at start, on the daily tick, after sleep, and on Refresh now. An old copy keeps a model that it proved free as free and flags it `cached <age>`; a model that no source proved free stays unknown (**fails closed on no proof**, not on age). A failed fetch keeps the last good table. The Models page lists each source with its basis, age, and fresh or cached state. Groq publishes no free-model list, so a Groq id stays unknown until the owner marks it free; that mark survives a stale snapshot. It does not scrape unofficial free-model websites and does not invent a pricing endpoint.

`KNOWLEDGE_CHECKED_AT` in `electron/model-access.cjs` is the knowledge date. A source's own date moves only after its page is re-read and matches its marker; a page without a price table (DeepSeek's pricing URL today) keeps its older date and the model stays unknown. A stale snapshot is never sent as a paid bill: the owner sees "pricing info is stale, refresh now" and can mark that model free. Startup and Refresh now re-read due pages when the PC is online and privacy mode is off; a page that does not match its marker leaves the last table. Consumer plan pages (ChatGPT, Claude, consumer Perplexity, Studio, Le Chat) are not API-free.

Live probe: existing `probeModel()` sends a tiny chat turn (stream first, then non-stream), checks HTTP success plus usable assistant text, and classifies auth, billing, quota/rate-limit, timeout, provider outage, network, context-overflow and stream failures separately. Streaming text is read from `choices[].delta.content`, `delta.text`, `choices[].text`, content parts, and `[DONE]`. Successful verification is cached (~30 minutes), synchronized into the kernel before dispatch, and surfaced through `keyConfigured`, `authenticated`, `catalogueFetched`, `pricingKnown`, `freeEligibilityKnown`, `freeModelAvailable`, `chatVerified` and `streamVerified`. The billing firewall remains the last authority.

**Which request passes which gate (verified by reading the code, 2026-11-18).** A chat turn to any model (chat, Auto, agents, workflows, schedulers, remote clients) goes `resolveChatModels` → `streamOnceRaw` → `authoriseProviderRequest` (privacy confirmation, then the billing firewall) → the kernel's `chat.stream`, where `kernel/router.py` `_stream_one` checks privacy and billing again. A health probe from Models and a capability check also pass `authoriseProviderRequest`. The one request that does not is the free-candidate verification probe in `models.cjs` (`lazyVerifyForRoute`, `probeAndStamp`): a fixed prompt with no user content, sent only to a model whose evidence says it may be free (`selectVerificationCandidates`), never on a private turn, offline, or under a paid-only policy. It is outside the gate on purpose: the billing firewall holds an unverified model back, and this probe is how a model becomes verified. The routing contract is mirrored in two places (renderer and main process); `core/__tests__/routing-contract-parity.test.ts` fails if their lists differ. The phone path (`kernel/main.py` `companion_chat`) reads the desktop's published snapshot, which now carries `privacy`, so a private target keeps a phone turn on this PC.

## 6. One routing contract

Chat, Voice, Auto, Manual, Multi, Companion, background tasks, agents and tool calls share one routing contract (`src/lib/friday/model-routing-contract.ts`, mirrored in `electron/model-router.cjs`):

- `routeMode`: `auto` | `local-only` | `cloud-only` | `hybrid` | `manual` | `multi`
- `costPolicy`: `free-only` | `free-first` | `balanced` | `quality-first` | `paid` | `paid-only`
- `qualityTarget`: `balanced` | `fastest` | `best-quality` | `cheapest` | `private` | `reliable` | `deep-reasoning` | `research-grade` | `local-preferred` | `cloud-preferred` | `diverse`
- `strategy`: `auto` | `single` | `fallback` | `parallel` | `race` | `cascade` | `pipeline` | `primary-critic` | `primary-verifier` | `candidate-judge`
- `task` / `requirements` (streaming, tools, vision, context, locality, privacy, strict evidence, allow inferred)
- `selectedModelIds` / `selectedProviderIds`

`balanced` is the default and adds nothing to the existing score. `fastest`, `best-quality`, `cheapest`, `reliable`, `deep-reasoning`, `research-grade`, `local-preferred`, and `cloud-preferred` only adjust that score. `diverse` adds nothing and then interleaves model families. `private`, and `requirements.privacy` of `private`, are a hard local filter: the prompt stays on this PC. Private together with cloud-only is an empty pool. The route mode is not rewritten to hide that. Local-preferred and cloud-preferred do not switch the route mode.

`strategy` defaults to `auto`. One chat stays a shortlist. A second-opinion run stays parallel until the owner picks another shape. Critic, verifier, judge, specialist, and synthesizer roles keep the owner's prompt and see earlier drafts. The judge is a different backend when one is in the shortlist. Fallback stops at the first answer and does not relax privacy, mode, tools, vision, context, or billing.

Hard filters run before the score, in this order: route mode, privacy, locality, provider, then the shared usable-model decision (not connected, retired, out of quota, cooldown, cost, not a chat model), then cloud opt-in, role, streaming, tools, vision, context, and evidence. A paid or unknown model with paid access off is rejected as cost. A cooldown is rejected as cooldown and stays visible in the selector, disabled. A retired or deprecated model is dropped. Vision and tools that exist only as a name guess are dropped unless the turn allows inferred evidence. `planRoute` returns the same candidate ids as `selectEligible`, a stable plan id, the steps, and a reason for each model the filters dropped.

HTTP 400 and HTTP 422 are `invalid_request`: not retryable, and the cooldown is 0 so the provider is not cooled down. A 429 uses Retry-After when the error carries one, capped at one hour; a bare rate limit still cools down for one minute. A daily cap stays an hour. A 5xx stays a retryable provider error. A rejected key and a missing model stay non-retryable.

The owner-selected route mode is never translated (`local-only` does not become `auto`; `cloud-only` does not become `manual`). Auto picks the best currently eligible model — it does not hardcode OpenRouter. Eligible means `usableModels()`: connected, and free or paid access on, and not retired. Paid and unknown-cost models enter only when paid access is on. A fallback stays inside that same set. Desktop chat and `kernel:rpc` both send the route mode so `kernel/router.py` can re-enforce local-only / cloud-only / manual, and a private turn, as the last safety boundary. The desktop logs one plan sentence; that log never changes who is selected.

The chat selector renders that same `usableModels()` result. A hidden row is not shown. A cooldown or an exhausted quota stays visible and disabled, with the reason. Each row reads `Provider · Model` plus `FREE`, `PAID`, `LOCAL`, or `cost unknown`. Owner-declared evidence adds the mark `owner declared`. After a turn, the message stores `answeredBy` from the router trace. The conversation strip shows that line once, with the step count and the chart button. The Flow Studio chat chart reads the same stored line. The message text stays the answer.

Failure handling on the same router. After one failed candidate the router orders what is left: the same model on another endpoint, a sibling on that provider, the same family on another provider, then any other model that already passed privacy and billing. A provider outage prefers a different backend. A deterministic 400 or 422, a content filter, a region block, and a context overflow do not move to another model (a context overflow moves only after the caller says the prompt was compacted). A refusal, a failed tool call, a schema mismatch, and low-confidence verification do move on, and they open no cooldown. A paid-access refusal cools that model only. A bad key, an offline engine, and a provider outage skip that backend. Three provider errors quarantine a model, three deterministic 400s do not, and a passed recovery probe clears it. The routable catalogue swaps only when the next list is an array of unique ids; a broken refresh keeps the previous generation. Multi plans name their aggregation (`parallel`, `staged`, `critic`, `verifier`, `judge`, `fallback`); only parallel and race fan out. Race and cascade are strategies on this router: a cascade orders cheaper models first, a race keeps the first success, and after three recorded trials success rate, latency, and owner feedback adjust the score without skipping a firewall. The chat path logs one execution trace and never sends it to the owner; the sentence drops hidden reasoning and secrets.

Error class is status first (HTTP status, then handler code, then a few exact phrases). A cloud failure never says the local engine is not running. Each failed attempt keeps provider, model, path, status, code, a short redacted body, elapsed time, and Retry-After. OpenRouter's `No endpoints found matching your data policy` is an account privacy setting, not a missing model. Ollama down ("Ollama not running") differs from a 404 tag (that id leaves the next route). Groq's zero `x-ratelimit-remaining-requests` is a daily cap, not a burst. Each handler exposes list URL, chat URL, a zero-spend probe label, and `mayTrain` (only OpenRouter `:free` sets it; strict privacy drops those models).

Catalogue and evidence refresh. One catalogue file per provider refreshes on startup only when missing or older than 24 hours, then on that interval, on Refresh now, after a model 404, and after sleep once 24 hours have passed. `planHealthProbe` refreshes the catalogue with jitter and spends nothing; `planModelProbes` adds a cached GET per model, skipped in privacy mode, and a failed probe cools that model before a turn. A light cooldown tick never calls a models endpoint. Privacy mode and a local-only route keep the disk copy and mark it stale. API key, endpoint, and route-mode changes invalidate immediately. TTLs: 10 minutes for a catalogue record, 30 minutes for pricing, 10 minutes for entitlement, 30 minutes for a successful probe. Lifecycle kinds (`MODEL_DISCOVERED`, `MODEL_VERIFIED`, `MODEL_FAILED`, `MODEL_RATE_LIMITED`, `MODEL_EXHAUSTED`, `MODEL_RETIRED`, `MODEL_REMOVED`, `PROVIDER_CONNECTED`, `API_KEY_CHANGED`, `ROUTE_CHANGED`) ride the existing `models:registry-changed`, `models:health-changed`, and `models:route-mode` broadcasts. Repairs that would rotate a key, change privacy, upload weights, enable a paid provider, or replace a pinned model stay with the owner (`models:heal` calls that gate).

Free lane and spend. `preferNewestFree` in `electron/model-router.cjs` orders the free lane: only a record `isVerifiedFree` accepts can move to the front, and a failed newest id falls back to the previous verified version. An unknown-cost model stays out of automatic routing; the owner can set `spendCapUsd` on it, and it is then treated as paid under the billing firewall. `recordSpend` adds one charge with the caller's time, rolls the day and month, and refuses a model id that looks like a key (`models:record-spend`). `budgetDecision` remains the cap. The kernel accepts official free evidence from the same source list as the desktop; stale, paid, exhausted, and unknown stay blocked. LM Studio rows that are not loaded stay on the Models page as `model not loaded in LM Studio` and are not routed; ids the OpenAI-compatible list serves (including JIT downloads) are routed, and a later "Please load a model" reply marks the id.

Models page card structure: the catalog and the online search show 40 rows, then Show more. Models groups LOCAL AI, CLOUD AI, and ROUTING.

### Escalation: FRIDAY Core, a heavier local model, or the cloud

`escalate(meta)` in `kernel/router.py` is one pure rule that never picks a model. FRIDAY Core keeps the turn unless it is a generation job, hard reasoning, code beyond Core, a context over 32K tokens, audio over 30 seconds or video over 60 seconds. Going up chooses a heavier local model first (`local_heavy`); the cloud is taken only after both firewalls: never for SENSITIVE content, never in private mode, never for a model of unknown cost, and a paid model only with paid access on. When the way up is closed the answer stays `core`, and the stream still runs the privacy and billing guards on whatever is chosen. `route_generation()` picks image, audio and video models under the same two firewalls and returns up to three candidates, best first; the desktop tries them in that order and the renderer cannot choose an ungated model: `model.route_generation` is on the renderer allowlist, but the main process removes any `explicitPaid` field from its parameters, so only the main process can mark a paid pick as the owner's. FRIDAY Core's own key is not a provider key: FRIDAY Runtime LLM makes one per launch, keeps it in memory, hands it to the server process through its environment and never writes it to disk. **Locality rule.** A model is local, and free, only when its endpoint is loopback or the engine host the owner set in this process's environment (`OLLAMA_HOST` and any other variable named in `kernel/local_engines.json`); the host is parsed from the URL and read from the environment at each call, never from a model row, a renderer message or a kernel RPC. The same rule is in `kernel/privacy.py`, `kernel/billing.py`, `electron/model-access.cjs` and `electron/privacy-firewall.cjs`, so a forged row with a remote endpoint is billed unknown and treated as external, and the kernel accepts a FRIDAY Core row only on loopback. The renderer cannot add, sync or remove the `friday-core` row (`touchesCoreRow` in `electron/main.cjs`). Tests: `core/__tests__/locality-rule.test.ts`, `kernel/tests/test_locality_rule.py`, `kernel/tests/test_router_core_trust.py`, `core/__tests__/friday-core-hardening.test.ts`. Licence and origin lines for the weights live only in the origins table of [docs/FRIDAY_VOICE_ENGINE.md](docs/FRIDAY_VOICE_ENGINE.md). Tests: `kernel/tests/test_router_core_escalation.py`, `core/__tests__/friday-runtime-llm-args.test.ts`. ## 7. Local launcher offers

`config/download-hosts.json` is the only remote download host list. `config/local-runners.json` holds the Windows asset pins. `electron/local-library.cjs` builds the card and the install offer. `electron/download-safety.cjs` is the transfer state machine and `electron/model-download.cjs` is the only public entry. ## Hardware-aware routing, offload hints and no-live-model (2026-11-23)

Everything here is unit-tested with fake probes and fake registries on Linux; real GPUs, drivers and engines on Windows are **unverified**.

- **One fact record.** `electron/hardware.cjs` `hardwareFacts(hw, deps)` builds `{vramGb, vramFreeGb, ramGb, ramFreeGb, diskFreeGb, gpuVendor, gpuName, gpus[{vendor,name,vramGb,driver,vramCapped}], cudaReady, driverVersion, npu, cpuClass, sources}` from `nvidia-smi` (parsed, with the CUDA header), `Win32_VideoController` (name and driver only; the 32-bit `AdapterRAM` is never trusted above 4 GB and sets `vramCapped`) and Electron GPU info. Nothing is guessed: a number appears only from a source (no memory probe means `ramFreeGb` and `cpuClass` are null). No code branches on a GPU name (grep-tested), so any Windows PC from small to large is read the same way. `hardware:facts` (quick) returns it to the renderer; Voice Diagnostics shows it as "This PC".
- **Learning from replies.** A cloud or unknown-origin reply never enters adapter training unless `outputMayTrain === true` (`src/lib/friday/self/finetune.ts`).
- **Routing.** `electron/model-router.cjs` `hardwareFit` scores each local model by what fits free VRAM and RAM with headroom (resident models are never demoted; unknown size or unknown facts give 0). A model that does not fit is **demoted, never hidden**. Order is unchanged: privacy firewall, then billing firewall, then choice; hardware only reorders models those filters allowed. `fanoutLanes` runs parallel/race local models one after another when they do not fit memory together (cloud lanes start together). The first turn waits at most once for the boot hardware probe, never on the voice surface.
- **Offload hint.** `plan.hardwareHints[modelId].offload` is `gpu`, `gpu-if-supported`, `cpu` or null; `cpu` is sent only when a probe found no usable GPU. It travels with that one request to the kernel, which validates it, applies it only to the model it names and never uses it to pick, add or unblock a model. Ollama gets `options.num_gpu = 0` for `cpu`; llama.cpp server (`-ngl`) and LM Studio set offload at launch or load time, so they get no per-request field. A GPU PC is never pinned to the CPU.
- **Kernel fallback order.** `kernel/router.py` ranks the fallback tail with the same surface score as `best_available` (voice latency-first, chat quality-first); the desktop's id order stays primary. A local engine that refuses connections (20 s) or a missing model (404 or not loaded, 60 s) is tried after live ones, never dropped; one error lists every route tried only when none answered.
- **No live model.** The Brain resolves a turn's model only against live registry rows (`resolveLiveRoute` in `src/lib/friday/model-routing-contract.ts`); a private or offline turn takes local rows only and billing-hidden rows never count. If no live row can answer and the owner pinned nothing, nothing is sent and one line appears in the owner's language (English, Hindi or Hinglish); chat and voice behave the same. A static catalogue id is never used as a fallback; a pinned model passes through.
- **Local engine trace.** `electron/model-routing-local.cjs` marks every local model that cannot serve a turn (LM Studio "not loaded", any other engine "not available" after a delist) so the route trace always says why; a pulled Ollama model that is not resident stays routable.
- Unverified: all score constants (-12, -4, +2) are reasoned, not measured; real Ollama/LM Studio/llama.cpp behaviour, `num_gpu: 0` on `/api/chat`, and `app.getGPUInfo` shape on Windows.


## Hardware plan, chat tiers and the context window (2026-11-28)

Linux unit tests only; nothing ran on Windows, a GPU, real Ollama pulls or a real context size (16k to 32k video-memory behaviour is unverified). The kernel tests could not run on this machine (`httpx` missing). One plan decides what setup, Doctor and the router use: `electron/setup-plan.cjs` with tiers in `config/chat-tiers.json` and facts from `electron/hardware.cjs`. Ollama tags were read on ollama.com/library on 2026-11-28.

- **Tier by total memory.** The tier follows total RAM; free memory only warns or defers a pull. The reserve interpolates below 8 GB: a 4 GB PC gets `qwen3.5:0.8b` at a 2048-token window, a PC with 3 GB or less gets no chat model. `gpu-4` is reachable (`qwen3.5:2b-q4_K_M`). New CPU tiers: `cpu-ram-24` (`qwen3.5:9b`), `cpu-ram-32` (`qwen3.6:35b-a3b`), `cpu-ram-64` (`qwen3.6:35b-a3b-q8_0`); new GPU tier `gpu-32` (`qwen3.6:35b-a3b-q4_K_M`). - **GPU rules.** NVIDIA follows Ollama's own rule (compute capability 5.0 or newer, driver 550 or newer, 570 or newer for compute 5.0 to 6.2; [docs.ollama.com/gpu](https://docs.ollama.com/gpu), read 2026-11-28). The parity fixture is `kernel/tests/fixtures/chat_ctx_parity.json`. The plan is warmed at boot and on a forced hardware probe (`warmChatPlan` in `electron/main.cjs`). There is no stored Settings key for the window; the environment value is the only override. `OLLAMA_FLASH_ATTENTION` takes only 0 or 1 ([docs.ollama.com/faq](https://docs.ollama.com/faq)); no code sets any Ollama environment value yet.

For surface `voice` and lane `quick`, `electron/model-router.cjs` adds +8 for it and `kernel/router.py` `pick_voice_fast` prefers it; a turn that `escalate()` sends up skips it. Lane `full` takes -4 only when a non-fast local model exists. The twin is local only and both firewalls run first. ## PC detection, resource governor and load leases (2026-11-23)

Everything here is unit-tested with fake probes, clocks and engines on Linux; **no PowerShell script, GPU, driver or Windows behaviour was run** (unverified until the owner's PC runs them).

- **Facts.** `electron/hardware.cjs` `hardwareFacts` now also reports: OS build, WebView2 and VC++ runtime; CPU model, cores, AVX/AVX2/AVX512; RAM and commit pressure (same thresholds as the speech kernel: high under 15% free clamped to 2 to 3 GB, critical under 7% clamped to 1 to 1.5 GB); per-drive free space, SSD/HDD, and which drive holds the data root and the model cache; Vulkan, driver date, integrated flag, multi-GPU; `cuda {driverCuda, cublas12, cudnn9, dllDirs, runtimeFilesFound}` (files are only stat-ed, never loaded; this does not replace the kernel's `cuda_runtime_ready` verdict); network (online, wifi/ethernet/cellular, metered, roaming, latency); power (battery, AC, plan, saver); and a `health` summary `{level: ok|tight|critical, reasons}` with stable codes (`ram-critical`, `disk-low`, `on-battery`, `metered-network`, `no-avx2`, ...). A fact no probe measured is `null`; nothing is guessed and nothing branches on a GPU name. All probes are asynchronous with timeouts and deadlines, cached (static facts 10 minutes, dynamic 20 s), and never block the main process; boot waits at most 2.5 s more for them. Network latency is measured only when privacy mode and local-only routing are off and the PC is online. Thermal state is not reported on Windows (Electron exposes it on macOS only).
- **Status page.** `/system` (full) and `/status` (compact) show these facts live through `hardware:facts` and `governor:status`, with loading, "measuring...", offline, error with Retry, and "not measured" states; a capped 32-bit video-memory reading shows as "at least 4 GB". No standing timer: refresh on mount, manual refresh, and on a pressure or governor notice (debounced), plus at most three one-shot retries 4 s apart while probes are still measuring.
- **Resource governor** (`electron/resource-governor.cjs`). Heavy consumers ask for a memory lease with a priority (voice, chat, background, prefetch); a lease is granted only if it fits after keeping desktop headroom (GPU max(0.5 GB, 10%), RAM 1.5 GB); otherwise it shrinks (smaller option or CPU offload hint), pauses lower-priority work, queues (bounded) or is refused with a reason. Downloads, installs, generations and model loads run through bounded queues with cancellation (caps 2, 1, 1, 1). Free RAM and video memory are read on the existing loop-lag window (no new timer); **high** pressure unloads idle Ollama models (only when their expiry stamp has not moved for 45 s) and the idle speech worker (after 60 s unused) and holds background work; **critical** also refuses new heavy non-voice leases and shows one notice line. On battery or a thermal speed limit it prefers smaller models and defers prefetch; voice is never paused. A main-process loop-lag p99 of 250 ms or more pauses background work (never voice).
- **No "Not responding".** The main window gets a native notice after 4 s, the existing reload prompt at 8 s, and one automatic reload after 90 s (cooldown 10 minutes); render-process-gone and child-process-gone (GPU) record diagnostics rows and recover through the existing interface-recovery and GPU guard.
- **Load leases** (`electron/load-lease.cjs`). Local chat model loads and the speech worker load ask the governor first (voice for the Auto turn, chat for foreground chat, prefetch for warm-ups; wait limits 1.5 s, 3 s, 0). A model that does not fit shrinks to the CPU plan or a smaller speech size; on refusal the turn moves to the next candidate with one plain line and the refused model is not marked unhealthy; **voice always loads** (a refusal loads the smallest installed size). No governor or unknown size means load exactly as before.
- Known gaps: embeddings load inside the kernel and have no lease yet (needs a small kernel op); battery saver is not wired (no Electron API; `getPower` passes false); the Ollama warm-up inside the load slot can wait up to 60 s on a cold model; the first boot starts two extra PowerShell processes whose cost is unmeasured.


## Install Manager catalogue, fit and updates (2026-11-23)

Unit-tested with fake feeds, facts and a fake pip on Linux; **GitHub release asset names, `digest` fields, real CUDA/Vulkan/CPU health checks, pip with `--require-hashes` and the roughly 1.2 GB downloads were not run** (the research sandbox blocked github.com): unverified until the owner's PC runs them.

- **Fit.** `electron/engine-fit.cjs` `classify(row, facts)` returns `supported`, `limited` or `unsupported` with reason codes, what the row needs (RAM, VRAM, disk, CUDA, driver minimum, Vulkan, AVX2, network, download size) and an alternative. A measured fact can make a row `unsupported`; an unknown fact only ever gives `limited`. Disk is checked against the model drive at 1.3 times the size; a metered line with a download of 500 MB or more, battery with a heavy GPU row, or busy RAM/VRAM give `limited`. `gpus[].computeCap` (from `nvidia-smi --query-gpu=...,compute_cap`, driver 510 and newer; older drivers give null and never rule CUDA out) rules CUDA builds below 7.5 out before install.
- **Catalogue.** `installer:catalog` (quick, never touches the network) returns every row (tool, engine, runtime pack, voice model, model) with fit, installed and latest version, update status (`current`, `update`, `unknown`, `error`), the source used, `checkedAt`, a stale flag and the split into supported, limited and unsupported lists, plus Doctor rows. `installer:refresh` starts a background check (manual refresh at most once a minute). `installer:update` needs the owner's consent under Ask every time and Balanced; Full autonomy may proceed (the dial value is passed by the renderer and not verified by main, as for `tools:run`).
- **Latest versions, official sources only.** Per row an ordered chain: GitHub releases API then releases.atom; PyPI JSON then PyPI Simple; Hugging Face API then the pinned revision; npm then its mirror; existing vendor feeds. Each source has a 6 s timeout and sends ETag or Last-Modified (304 serves the stored copy); answers are cached in `<root>/cache/vendor-feeds.json`; offline the cached value shows as stale. The daily refresh rides the existing catalogue refresh (no new timer), skips in privacy mode or offline, and after failed passes backs off (5, 10, 20 minutes ... up to 24 h; a manual refresh is never delayed).
- **Digests.** Every download is checked against the digest the official API or index published (GitHub asset `digest`, PyPI sha256, Hugging Face LFS sha256) and deleted on a mismatch; a candidate with no digest is refused; a vendor digest that disagrees with the pin for the same version is refused; a data-file installer (exe, msi, msix) is also signature-checked and a stored version becomes the rollback floor only after a verified digest (details in `docs/FRIDAY_BUILD_AND_RELEASE.md`); all sources failing leaves the old install untouched.
- **llama.cpp.** The build is chosen from facts: CUDA 12 plus its cudart zip needs an NVIDIA card, driver CUDA 12 or newer, compute capability 7.5 or newer and at least 4 GB free VRAM; otherwise Vulkan on a real device; otherwise CPU (AVX-512, AVX2 or plain). After unpacking a 3 s health check runs; on failure the build is removed and the next step down is tried, recorded in `.friday-engine.json`. Install path `runtime/engines/llama.cpp/<tag>-<variant>`, built as `.staging`, swapped through `.prev`; the active folder is the one installed last (marker `installedAt`), a folder just installed or in use is never pruned and the newest two are kept.
- **CUDA runtime libraries.** cuBLAS 12.9.2.10 (553,162,896 bytes) and cuDNN 9.28.1.4 (696,300,805 bytes), read from PyPI, installed on demand on NVIDIA PCs only with `pip --require-hashes` into the FRIDAY Python environment where `kernel/stt.py` looks; NVIDIA proprietary licence, never bundled.
- **ONNX Runtime** has three variants (CPU, DirectML, GPU) that are never installed together; a switch copies and hashes the installed version first, and a failed switch removes the new wheel and restores the old one from that local copy with `--no-index --require-hashes`; the result message says plainly when the old one could not be put back. **FFmpeg** (LGPL shared build, separate process) and **stable-diffusion.cpp** are optional rows with the same fit and fallback logic.
- **CUDA file search.** Local fixed drives only (never UNC shares), at most 40 folders, 4 file checks at a time, cached 10 minutes.
- Known gaps: no pip-route fallback for llama-cpp-python after a failed import; voice-model and runtime-pack updates go through their own installers (the catalogue only reports them); asset names for stable-diffusion.cpp executables and the GitHub `digest` field need a first real install to confirm.
