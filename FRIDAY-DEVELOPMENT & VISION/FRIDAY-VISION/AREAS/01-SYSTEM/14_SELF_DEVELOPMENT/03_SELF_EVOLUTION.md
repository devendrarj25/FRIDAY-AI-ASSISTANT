# Self-Evolution

## Purpose
Evolve capabilities, workflows and architecture through explicit staged proposals, never through uncontrolled runtime self-modification.

## Canonical flow
Need/opportunity → research → design candidate → sandbox prototype → evaluation → compatibility/security review → staged activation → observe → graduate/rollback.

## Required contracts
Evolution proposal is separate from immutable policy and owner identity.

## Failure and recovery
Evolution cannot delete governance, weaken approval, expose secrets or create an unbrokered executor.

## Implementation guidance
Use capability discovery, workflow forge, agent forge, module forge and dev pipeline.
