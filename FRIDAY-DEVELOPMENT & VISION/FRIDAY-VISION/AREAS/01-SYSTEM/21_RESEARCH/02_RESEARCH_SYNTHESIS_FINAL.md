# Research Synthesis — Final

Across the reviewed ecosystem, the strongest recurring lesson is that “smart” is not a single larger model. Reliable AI OS behavior comes from a system that combines durable state, good routing, specialized capabilities, realtime control, verification, memory, governance and recovery.

## Patterns FRIDAY should absorb
1. **Always-on operating layer:** background listeners, scheduled work and proactive briefings, but with resource and privacy controls.
2. **One persistent state:** no cold-start loss when switching models, modalities or sessions.
3. **Task as a first-class object:** every substantial request has state, plan, evidence and history.
4. **Event-driven runtime:** realtime activity and recovery become easier when execution emits canonical events.
5. **Accessibility-first computer use:** deterministic semantic control is cheaper and safer than visual clicking when available.
6. **Browser experience memory:** learn workflows, but re-observe live state and never trust stale selectors.
7. **Full-duplex voice:** listen while speaking, support barge-in, preserve spoken cursor and continue the same task.
8. **Self-improvement as experimentation:** candidate → evaluation → canary → promote/rollback, not unrestricted self-editing.
9. **Anti-anchoring:** explore multiple repair hypotheses on hard failures rather than reinforcing one diagnosis.
10. **Zero-trust tool ecosystem:** MCP/A2A/plugins/remote agents are integration protocols, not inherited authority.
11. **Durable side effects:** idempotency keys and ambiguous-outcome recovery prevent duplicate real-world actions.
12. **Resource-aware autonomy:** background intelligence must respect CPU/GPU/RAM, foreground use and battery/thermal pressure.
13. **Epistemic honesty:** distinguish attempted from verified success.
14. **Temporal memory:** facts change; FRIDAY must represent validity intervals and contradictions.
15. **Goal/commitment layer:** proactive behavior should come from explicit goals, promises and schedules, not arbitrary model initiative.

## What FRIDAY should not copy blindly
- UI designs from other products;
- provider-specific state formats;
- unverified benchmark claims;
- direct self-modification in production;
- unrestricted browser credentials;
- public exposure of privileged desktop control;
- a second orchestration framework where FRIDAY already has an owner.
