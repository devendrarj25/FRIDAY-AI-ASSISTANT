# Final Implementation Phase Plan

## Phase 0 — Inventory and ownership
Map every target concept to existing FRIDAY owner files. Fail if a second owner would be created.

## Phase 1 — Canonical envelopes and event spine
Unify turn/task/plan/route/capability/action/result/verification/event identity. Keep existing IPC/event channels compatible.

## Phase 2 — Durable execution
Add journal/checkpoint/idempotency/recovery semantics around the existing task/execution machinery.

## Phase 3 — Policy and evidence
Make governance the pre-effect gate and verification the post-effect truth boundary.

## Phase 4 — Routing/model federation
Unify existing registries and health information into adaptive, provider-independent routing.

## Phase 5 — Memory/world/goal OS
Strengthen temporal memory, beliefs, contradictions, goals, commitments and experience replay.

## Phase 6 — Computer-use ladder
Prefer existing APIs/accessibility/browser mechanisms; add visual fallback only where needed; add yielding and verification.

## Phase 7 — Realtime modalities
Harden full-duplex voice, cross-modal steering and Companion continuity.

## Phase 8 — Self-learning/development
Add outcome learning and sandboxed eval-gated self-improvement without direct production mutation.

## Phase 9 — Observability/performance
Add canonical traces, evaluation, resource governor and failure-injection coverage.

## Phase 10 — Final regression
Prove manual build, installer, packaged build, runtime boot, kernel health, core Chat, Voice, Manual, Auto, Companion and protected release path. Do not redesign UI.
