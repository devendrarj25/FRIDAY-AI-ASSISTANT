# Merge Decisions and Conflict Resolution

## Authority order
1. Existing FRIDAY source reality.
2. Existing FRIDAY System OS architecture.
3. Existing FRIDAY Brain architecture.
4. This integrated interaction architecture.
5. Supplied Chat/Voice package details, reconciled when compatible.
6. Research patterns, adopted only when they fit FRIDAY ownership and governance.

## Conflicts resolved
- Chat package scoped Manual; System architecture requires Manual and Auto as independent operating axes → merged into dual-axis model.
- Voice package contains voice-specific runtime details; System architecture requires one brain → retained media/session pipeline while routing all cognition/task state into shared runtime.
- Mobile is treated as an experience endpoint, not a separate backend.
- Existing task graph/ledger remains task authority; no A2A/LangGraph/Temporal-style replacement is introduced.
- Existing governance remains the authority; Auto is not blanket approval.
- Existing event/bridge infrastructure remains the event owner; no second event bus.

## What was intentionally not copied as a duplicate
The original ZIP directory trees are not embedded inside this package. Their requirements are represented in the integrated architecture plus source coverage ledgers so implementation has one authoritative place to follow.
