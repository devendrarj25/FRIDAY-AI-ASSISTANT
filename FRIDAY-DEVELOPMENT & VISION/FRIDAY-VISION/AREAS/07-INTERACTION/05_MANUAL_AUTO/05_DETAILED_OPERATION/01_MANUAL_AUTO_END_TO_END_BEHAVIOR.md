# Manual + Auto — End-to-End Detailed Behavior

## Manual mode
The owner controls progression through explicit interaction. FRIDAY can continue assigned background/self-learning/self-development work under existing policy, but user-facing actions that require intervention remain visible and gated.

### Example
Chat: “Research these products and make a report.”
- FRIDAY creates one durable task.
- Work runs through shared Brain/Task/Capability/Governance systems.
- Chat can be closed without destroying the task.
- Mobile can inspect it.
- Voice can steer it.
- Approval pauses at the same central gate.
- The final report is one artifact visible everywhere.

## Auto mode
Auto adds an autonomy grant to the same runtime. It does not fork the task or create an AutoBrain.

### Example
User enables Auto and says: “Every weekday, monitor this project and prepare a morning report.”
- scheduler creates/continues the canonical task/workflow
- execution uses existing capability and resource systems
- safe permitted work proceeds without intermediate UI clicks
- significant milestones/errors/approval needs become events
- owner approval remains required for gated actions

## Switching Manual ↔ Auto
Switching mode updates policy for the active task. It does not duplicate the task, restart memory, or reset the Brain.

## Closing the UI
Closing Chat, Voice, or Mobile disconnects a surface. It does not imply task cancellation.

## Reopening
The new surface rehydrates canonical state and resumes observation.
