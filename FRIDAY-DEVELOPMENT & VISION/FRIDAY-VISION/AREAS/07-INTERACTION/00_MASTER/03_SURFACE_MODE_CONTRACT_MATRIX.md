# Surface × Mode Contract Matrix

| Surface | Manual | Auto | Shared authority |
|---|---|---|---|
| Desktop Chat | user-directed turns, gated approvals | autonomous eligible work, visible progress | Brain/task/governance/event fabric |
| Desktop Voice | spoken commands, explicit gates | autonomous work with spoken milestones | same |
| Mobile Chat | complete remote chat controls, approvals, steering | same autonomous task observation/control | same |
| Mobile Voice | mobile mic/speaker/camera where browser permits | same | same |
| Notifications | attention only | attention only | points to authoritative state |

## Surface parity
Parity means semantic capability parity, not pixel-identical UI. A surface must expose every capability it can safely and technically represent, clearly mark unsupported/degraded capabilities, and never invent support.

## Mode parity
Manual and Auto differ in authority policy, not in Brain architecture. A task can continue across mode/surface transitions without changing its canonical identity.

## Cross-surface handoff
Every handoff carries canonical IDs and the latest verified checkpoint. The receiving surface rehydrates from authority; it does not trust a serialized UI snapshot as truth.
