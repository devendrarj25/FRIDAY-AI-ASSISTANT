# Migration Sequence

### Phase 0 — Contract only
Add schemas/types/tests. No behavior change.

### Phase 1 — Shadow registry
Mirror existing trees into canonical capability registry. Compare counts and IDs.

### Phase 2 — Broker shadow
Run broker decisions beside current routing; compare selected resources.

### Phase 3 — Tool/skill/agent adapters
Route one capability family at a time.

### Phase 4 — Durable task runtime
Move long-running workflows to persistent task state.

### Phase 5 — Feature runtime
Promote high-value outcomes into feature manifests.

### Phase 6 — Computer use
Unify browser + desktop under perception/action adapters.

### Phase 7 — Interop
Normalize MCP/A2A/plugins/connectors.

### Phase 8 — Full cutover
Broker becomes canonical; legacy trees remain compatibility surfaces.

### Phase 9 — Optimize
Add proactive activation, capability learning, cache, speculative execution and adaptive routing.
